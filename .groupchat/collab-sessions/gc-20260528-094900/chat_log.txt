## 群聊开始时记忆轮询机制

**核心结论：直接用用户消息内容进行语义搜索，不需要先问AI搜什么。**

### 召回流程 (`_auto_recall.py`)
1. **输入**：`user_input`（用户刚发的消息文本）
2. **关键词生成**（可选增强）：`_generate_wing_queries(user_input, engine)` — 一次LLM调用，生成3个wing的检索关键词
3. **语义搜索**：对每个wing调用 `L3.search(query=query, wing=wing, n_results)` 
   - 有 query 时用语义搜索
   - 无 query 时 fallback 到 L2.recall (按插入顺序返回)
4. **注入系统消息**：搜索结果拼入 agent 的系统提示词

### 三个 Wing
| Wing | 内容 |
|---|---|
| `wing_code` | 技术上下文、工具用法、踩坑记录 |
| `wing_user` | 用户偏好、输出风格、交互习惯 |
| `wing_agent` | 事实数据、发现、规则约定 |

### 关键演进
- **之前**：非语义的元数据过滤 + 插入顺序返回（L2.recall）
- **现在**：`L3.search()` 语义搜索，基于用户输入动态匹配最相关内容
- **存储端**：讨论结束后由LLM提取信息写入ChromaDB（`_auto_memory.py`）

所以答案是：**直接用用户消息内容做语义搜索 query**，不需要先问AI搜什么。关键词生成是可选的增强步骤（当用户输入模糊时可加），但默认方案直接用原始输入就够用了。
