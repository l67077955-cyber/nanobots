[Kirk]: ## 结论

当前启动总耗时 **9.58s**（kernel 3s + userspace 6.58s）。最大瓶颈是 `systemd-networkd-wait-online` 白等了 2 分多钟——你用的是 NetworkManager，根本不需要 networkd 等网络。

## 关键发现

| 服务 | 耗时 | 说明 |
|---|---|---|
| `systemd-networkd-wait-online.service` | **2min 9s** | 最大元凶，等网络就绪 |
| `apt-daily-upgrade.service` | **1min 24s** | 开机自动更新包 |
| `apt-daily.service` | **1min 9s** | 开机更新索引 |
| `docker.service` | **2.77s** | Docker 守护进程 |
| `snapd.seeded.service` | **2.18s** | Snap 初始化 |

**关键路径**：`graphical.target` ← `docker.service` ← `containerd.service` ← `NetworkManager` ← `snapd.socket`

## 优化建议

**1. 禁用 `systemd-networkd-wait-online`（省 ~2min）：**
```bash
sudo systemctl disable systemd-networkd-wait-online.service
```

**2. 禁用 `snapd`（省 ~2s，如不用 snap 包）：**
```bash
sudo systemctl disable --now snapd.service snapd.socket
```

**3. Docker 改为按需启动（省 ~2.8s）：**
```bash
sudo systemctl disable docker.service containerd.service
```
首次执行 `docker` 命令时会自动拉起。

## 备注

- `snapd.service` 显示 1w2d 是**历史累计运行时间**，不是本次启动耗时。
- apt 定时任务跑在后台，不阻塞 graphical.target，影响不大。
- 做完优化 1 后预计启动降到 ~7.5s。
