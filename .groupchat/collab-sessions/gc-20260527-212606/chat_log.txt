## 当前轮询逻辑

`_auto_recall.py` 对 3 个 wing **用同一个 `user_input` 做 query**：

```python
for wing, label, desc in _RECALL_WINGS:
    content = _recall_wing(wing, query=user_input)  # 同一个 query
```

3 个 wing：
| wing | 标签 | 搜索方向 |
|---|---|---|
| `wing_code` | 技术上下文 | 工具用法/方法/踩坑 |
| `wing_user` | 用户偏好 | 输出风格/交互习惯 |
| `wing_agent` | 固定信息 | 事实数据/发现/规则 |

**问题**：同一个 `user_input`（比如"看看mempalace的轮询逻辑"）同时搜 3 个 wing。`wing_user` 里存的是用户偏好（输出风格、交互习惯），跟"轮询逻辑"语义上完全不相关，但 ChromaDB 语义搜索可能还是会返回一些勉强匹配的结果——**这就是噪音**。

## 你说的"给出关于对（工具/用户/纯信息）的搜索关键词"

意思是：**不是用一个 query 搜所有 wing，而是让 LLM 针对 3 个 wing 分别生成不同的检索关键词**。比如用户说"看看mempalace的轮询逻辑"：

- `wing_code` → "mempalace auto recall search semantic ChromaDB"
- `wing_user` → "用户偏好 记忆搜索 输出风格"  
- `wing_agent` → "记忆协议 SOP 规则约定"

这样每个 wing 用**针对性关键词**搜，而不是用同一个模糊 query 搜所有 wing。

**这个想法是对的，比当前实现更精确。** 要改吗？改动很小——加一个 `_generate_wing_queries(user_input)` 函数，LLM 一次调用返回 3 组关键词，然后分别喂给 `L3.search`。

[Kirk]: ## 结论
MemoryPalace 轮询逻辑已改为**语义搜索 + LLM 动态生成关键词**。每轮讨论前，系统根据用户输入为 3 个 wing（工具/用户/纯信息）分别生成针对性检索词，不再是无差别的固定召回。

## 改动内容

**`_auto_recall.py`**（68→130行）：
- 新增 `_generate_wing_queries(user_input, engine)` — 一次 LLM 调用，根据 `_RECALL_WINGS` 的 desc 为 3 个 wing 分别生成检索关键词
- `_recall_wing(wing, query)` — 有 query 走 `L3.search()` 语义搜索，无 query fallback 到 `L2.recall()`
- `auto_recall_memories(user_input, engine)` — 有 engine 走 LLM 关键词路径，无 engine fallback 到 raw user_input

**`run_loop.py`**：1 行改动 — 传入 `engine=engine`

## 工作流程（改动后）
```
用户输入 → LLM生成3组wing关键词 → 分别L3.search → 合并注入系统消息
```
