[Harper]: ## 痛点解决方案

### 问题本质
config 是独立 Git 仓库，主仓库无法感知其版本变化，导致部署时配置与代码不匹配。

### 推荐方案：B（version-lock.json + CI 自动同步）

**原理：** 主仓库记录 config 的 pinned commit，CI 检测 drift 并可选自动更新。

#### Step 1: 创建 version-lock.json
```bash
cd /root/nanobot-src
cat > version-lock.json << 'EOF'
{
  "config": {
    "path": "config",
    "repo": "./config",
    "pinned_commit": "56c9bed",
    "updated_at": "2026-06-07"
  }
}
EOF
```

#### Step 2: 添加 CI 检查 job（在现有 workflow 加一段）
```yaml
  config-sync:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      
      - name: Check config version lock
        run: |
          PINNED=$(jq -r '.config.pinned_commit' version-lock.json)
          ACTUAL=$(git -C config rev-parse HEAD)
          echo "Pinned: $PINNED"
          echo "Actual: $ACTUAL"
          if [ "$PINNED" != "$ACTUAL" ]; then
            echo "::warning::Config repo is ahead of locked version!"
            echo "Run: jq '.config.pinned_commit=\"$ACTUAL\"' version-lock.json > tmp && mv tmp version-lock.json"
          fi

      # 可选：自动更新（PR 时触发）
      - name: Update lock file
        if: github.event_name == 'pull_request'
        run: |
          git -C config fetch origin main
          git -C config checkout main
          ACTUAL=$(git -C config rev-parse HEAD)
          jq ".config.pinned_commit = \"$ACTUAL\" | .config.updated_at = \"$(date +%Y-%m-%d)\"" \
            version-lock.json > tmp.json && mv tmp.json version-lock.json
```

#### Step 3: 开发流程规范（新 PR 必须通过 CI）
```
代码变更 → 更新对应配置文件 → 更新 version-lock.json → PR 通过 CI 检查 → Merge
```

| 方案 | 改动量 | 控制粒度 | 推荐场景 |
|------|--------|----------|----------|

| A (submodule) | 中 | 高 | 需要严格绑定版本 |

## 关键发现修正

之前表述"配置仓库"有误——**config/ 实际上是 Memory-Palace 仓库的克隆**：

| 属性 | 值 |
|------|-----|
| remote URL | `github.com/AGI-is-going-to-arrive/Memory-Palace.git` |
| 当前 commit | `56c9bed`（与 Memory-Palace 仓库一致） |
| 目录用途 | 记忆宫殿数据（含配置、profile、frontend 等） |

所以真正的架构是：
```
主仓库(nanobot-src) ──(未注册submodule)──> Memory-Palace仓库(物理存在于config/)
```

## 方案A 的两个变体

**A1：把 Memory-Palace 注册为正式 submodule**
```bash
git submodule add https://github.com/AGI-is-going-to-arrive/Memory-Palace.git config
git add .gitmodules config && git commit -m "chore: add Memory-Palace submodule"
```

**A2：仅用 version-lock.json 追踪（更轻量）**
- 保持现状结构（config/ 已指向正确 remote）
- 主仓库加 `version-lock.json` 记录 Memory-Palace commit
- CI 检查 drift

---

**我的建议：采用 A2。** 理由：
1. Memory-Palace 作为独立知识库，不应被强制耦合到 nanobot-src 的生命周期
2. version-lock 已能满足"部署时版本对齐"需求
3. 不改变现有目录结构，改动最小

如需更严格管控（比如某些配置文件必须与代码版本绑定），再用 A1。
