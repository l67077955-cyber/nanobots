## 核心思路：从输入本身推断长宽

**行数 = 高，第一行长度 = 宽。**

### Python 示例

```python
import sys

grid = sys.stdin.read().splitlines()
H = len(grid)          # 行数即高度
W = len(grid[0])       # 第一行长度即宽度

# 然后正常遍历 grid[i][j]
```

### C++ 示例

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    vector<string> grid;
    string line;
    while (getline(cin, line)) {
        if (line.empty()) continue;  // 跳过空行
        grid.push_back(line);
    }
    int H = grid.size();
    int W = grid[0].size();
}
```

### 注意事项

| 情况 | 处理 |
|---|---|
| 行末有 `\r`（Windows换行） | `line.strip('\r')` |
| 行长度不一致 | 取 `max(len(row) for row in grid)` 或按需补齐 |
| 有空行分隔 | 过滤掉空行再算 |
| 输入混有其他数据（如起点坐标） | 先读非地图数据，剩下的 `splitlines()` 就是地图 |

**本质上就是一行代码的事**——`H = len(grid)`，比给长宽还省事，因为不用解析前面的数字。

## 补充：边界情况

**1. 空格分隔的矩阵**（每个格子是"0 1 0"而非"010"）
```python
grid = [line.split() for line in sys.stdin.read().splitlines() if line.strip()]
H = len(grid)
W = len(grid[0])  # 此时是列数，不是字符数
```

**2. 文件末尾空行陷阱**
```python
lines = sys.stdin.read().strip().splitlines()  # strip() 干掉末尾空行
H = len(lines)
```

**3. 比给长宽更好的理由**
- 少解析一行数字，代码更短
- 不会出现"声明了10x10但实际输入只有8行"的bug
- 输入格式变了也不用改代码

**本质上：输入没给长宽不是缺陷，是设计——省了你自己算。** 一行 `H=len(grid)` 搞定。

[Kirk]: **不麻烦，一行代码搞定。**

核心：`H = len(grid)`，`W = len(grid[0])`。行数即高，第一行长度即宽。

唯一要注意的坑：
- **空格分隔**（`0 1 0` 而非 `010`）→ 用 `line.split()` 而非直接当字符串
- **末尾空行** → 先 `.strip()` 再 `.splitlines()`
- **Windows换行 `\r`** → `.strip('\r')`

没给长宽反而更好——少解析一行数字，不会出现"声明10×10但实际只有8行"的bug。
