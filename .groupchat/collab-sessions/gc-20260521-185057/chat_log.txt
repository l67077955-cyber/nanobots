[Kirk]: ## 结论

重构计划定稿。6 阶段 5 天工期，核心改动 Phase 0-3（3.5 天）解决分散问题，Phase 4-5 可后置。

## 关键发现

**采纳 Harper 的 3 项修正：**

1. **双入口接口**（非单一 `run(messages)`）
   - `process_tool_result(tool_msg)` → S1+S2 增量处理单条工具结果
   - `maybe_compress(messages)` → S3+S4 全局压缩
   - 原因：S1/S2 是每次工具返回后增量触发，S3/S4 是 `add_message` 时全量触发，统一接口会退化

2. **错误恢复策略**
   - 每 Stage 加 `graceful_fallback`，异常时保持 messages 原样不中断会话
   - 现有代码的容错机制（静默返回原始内容）必须保留

3. **Phase 0 测试覆盖 12 个**（非 4 个）
   - S1: 超大结果 / 空结果 / 阈值边界
   - S2: LLM 返回空 / 纯元信息 / 超时
   - S3: soft+keep_recent保护 / hard cap突破保护 / user/assistant不可修改
   - S4: 丢弃<5条不调LLM / 丢弃≥5条调LLM / 摘要注入位置
