## 结论

**根因：`tool_result_brief` 对 memory_palace 的判断逻辑有 bug。**

`display.cpython-312.pyc` 第403行：
```python
if result and 'stored' in result:
    return '    └ ✅ stored'
```

这是**纯子串匹配**，不区分 action 类型。当 `memory_palace(search)` 返回的记忆内容中恰好包含 "stored" 这个词时（比如之前存过关于 store 功能的记忆文本），就会误触发 `✅ stored` 的 brief 显示。

## 关键发现

- search 返回格式：`🔍 X result(s) for '...'` + 记忆内容文本
- store 返回格式：`✅ Stored in wing/room` + drawer ID 等
- 两者都经过同一个 `'stored' in result` 检查，search 的记忆内容可以包含 "stored" 这个词
- **只有 .pyc 无 .py 源码**，位于 `/root/nanobot-src/nanobot/groupchat/display/__pycache__/display.cpython-312.pyc`

## 修复方案

将第403行的子串匹配从 `'stored' in result` 改为 `'✅ Stored in' in result`（或 `'Stored in' in result`），与 store 操作的实际返回前缀精确匹配，消除 search 结果的误判。

## 结论

**根因**：`tool_result_brief` 对 `memory_palace` 工具用 result 文本做子串匹配来判断 action 类型（search vs store），而不是用 `action` 参数。

**触发条件**：`memory_palace(search)` 返回的搜索结果文本中不包含 "search" 但包含 "stored"（比如搜到的记忆内容里有 "✅ stored"），导致：
- 第70行 `'search' in result.lower()` → False
- 第72行 `'stored' in result` → True → 误显示 `✅ stored`

**Retriever 的修复建议 `'✅ Stored in' in result` 是治标不治本**——仍然依赖 result 文本匹配，只是缩小了误判面。如果搜索结果里恰好包含 "✅ Stored in" 一样会误判。

**正确修复**：函数签名加 `action` 参数，调用处从 tool_call 的 params 里提取 `action`，直接按 action 值分发显示逻辑。`tool_result_brief(name, tool, result, action=None)`，然后：

if tool_name == 'memory_palace':
    if action == 'search':
        return '    └ 🔍 found'
    if action == 'store':
        return '    └ ✅ stored'
    return f'    └ ({rlen:,}字)'
