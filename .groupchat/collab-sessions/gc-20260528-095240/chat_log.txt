## 结论

nano 收到的完整 `user_input` 是：
```
我现在给一张图片，看看nano会搜索什么
[image: /root/.nanobot/media/telegram/AgACAgEAAxkBAAEC.jpg]
```

nano **看不到图片内容**，它只拿到这段纯文本。它会基于"图片路径+用户文字"生成关键词，大概类似：

```json
{
  "wing_code": "图片 image 搜索 nano 记忆检索 _generate_wing_queries auto_recall",
  "wing_user": "用户偏好 图片 测试 看看 搜索行为",
  "wing_agent": "图片 image nano 模型 记忆轮询 搜索关键词"
}
```

**核心问题：nano 是纯文本模型，图片对它来说就是一行 `[image: /path/to/file.jpg]`，它无法理解图片内容。** 搜索结果会偏向"记忆检索机制"相关记忆（因为用户文字在问这个），而不是图片实际内容。

## 关键发现

- **图片处理链路**：`message_handler.py:53-93` → 图片下载到本地 → 拼接为 `[image: {file_path}]` 文本 → 与用户文字用 `\n` 连接
- **voice/audio 有特殊处理**（Groq 转写为文字），**image 没有**——直接当路径字符串
- **截断**：`user_input[:500]`（第89行），图片路径很短不会触发
- **降级**：如果 nano 生成的 JSON 解析失败，3个 wing 全部用原始 `user_input`（含图片路径）直接搜

## 备注

如果想让图片内容参与记忆检索，需要在 `message_handler.py` 的 image 分支加视觉模型描述步骤（类似 voice 的 Groq 转写），把图片描述文本拼入 `content_parts`。当前架构下图片内容对记忆检索完全不可见。
