## 记忆存储触发时机

**1. 任务完成后（强制）**
每条 prompt 末尾明确写着：
> 「任务结束时，将关键结论写入记忆宫殿（memory_palace store），确保后续可复用。」

**2. 发现新方法/工具/技巧后（立即）**
tool_instructions.md 规定：
> 「发现新方法、新工具、新技巧后，**立即**用 memory_palace(store) 写入」
> 「不要等到任务结束才写——成功验证后下一个动作就是存记忆」

**3. 搜索到关键数据后**
> 「关键数据搜到即写（防丢失），结束时补充完整」

**4. 发现错误记忆时**
> 「发现错误记忆立即删除，不完善的修正重写」

---

### 不触发的情况
- **临时状态、任务进度、过程日志** — 这些属于 prompt/短期上下文，不存
- **操作协议、行为规则** — 已在 prompt 中每轮加载，零检索成本

简单说：**持久有用的事实 → 写完就存；临时过程信息 → 用完即弃。**

[Kirk]: ## 结论

记忆存储**不是自动触发**的，是 agent 主动调用 `memory_palace store` 的。触发时机有 3 个硬性规则：

1. **任务完成后** — 必须将关键结论写入
2. **发现新信息时立即写** — 新方法/工具/技巧验证成功后，下一个动作就是存记忆，不等任务结束
3. **end_discussion 前** — 存记忆 → end_discussion 是强制顺序，未存则禁止结束

## 关键发现

- 存什么：持久有用的事实（用户偏好、环境配置、工具坑点、稳定约定）
- 不存什么：任务进度、临时状态、过程日志、操作协议（这些属于 Prompt 层）
- **已知问题**：agent 经常跳过 store 步骤，这是"搜不到记忆"的常见原因之一——规则明确但执行率不保证，依赖 agent 自觉遵守 prompt 指令
