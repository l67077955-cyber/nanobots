[Kirk]: ## 结论

Kirk 没有通过任何"单独退出"逻辑退出。Kirk 调用了 `end_discussion`（🏁），这是 Leader 专属工具，会终止整个群聊。Harper 之所以在 Kirk 退出后仍在执行，是因为 **autowait 竞态条件**。

## 关键发现

**退出机制**（`broadcast.py` `_run_one()`）：

| 路径 | 触发者 | 效果 |
|------|--------|------|
| `end_discussion` 工具 | **仅 Leader** | 设置 `leader_end_event` → 外层循环 cancel 所有 Worker task |
| `max_cycles` 硬上限 | 任何 agent | Leader=30, Worker=20，强制退出该 agent |
| `engine._running=False` | `/stop` 或 end_discussion | 所有 agent 的 wait() 返回 None 后 break |
| `CancelledError` | Leader end_discussion | Worker task 被 cancel() |
| 连续 LLM 错误 ×3 | 任何 agent | 强制退出该 agent |

**不存在"远古的单独退出逻辑"**——所有退出路径都是当前活跃代码。

## 那次 Kirk 退出的根因

**时序竞态**：

1. Kirk 在 cycle 7 调用 `end_discussion`
2. `EndDiscussionTool.execute()` 的 autowait guard（L1105-1125）检查 `mailbox._active_agents - mailbox._waiting`
3. **此时 Harper 恰好处于 `wait()` 状态**（在 `mailbox.wait(name, timeout=600)` L1267），所以 `_waiting` 包含 Harper → `non_waiting` 为空 → guard 通过
4. `end_discussion` 执行：`leader_end_event.set()` + `engine._running = False`
5. 外层循环（L1564-1572）检测到 sentinel 完成，cancel 所有 Worker task
6. **但 Harper 在 cancel 到达之前已经收到了 Kirk 的最终回复消息**（通过 `chatroom_send`），从 `wait()` 返回，进入新一轮 tool_loop 执行 `git tag`
7. `task.cancel()` 在 Harper 执行 `exec` 工具期间到达，但 `exec` 是同步阻塞调用，`CancelledError` 只在下一个 `await` 点触发
8. Harper 完成了 `git tag`，然后才被 cancel

**本质**：autowait guard 只检查**快照状态**。Harper 在 `wait()` 中时看起来是"空闲"的，但收到消息后会立即重新激活。guard 通过 ≠ Worker 真的没事了。

## 备注

- 这是一个已知的竞态窗口：autowait guard 通过 → end_discussion 执行 → Leader 的最终文本通过 `chatroom_send` 发给 Worker → Worker 从 wait() 醒来 → Worker 开始新 cycle → cancel 到达但 Worker 已在执行中
- 修复方向：autowait guard 应该在通过后**锁定** Worker 的消息队列，或者 end_discussion 后不再向 Worker 投递新消息
