[Kirk]: ## 结论

**进程内一致，跨进程不持久。** 动态编排生成的历史在单次进程生命周期内是确定性的（相同输入→相同输出），但进程重启后历史完全丢失，无法恢复。

## 关键发现

### 持久化现状

| 数据 | 是否持久化 | 机制 |
|------|-----------|------|
| **消息历史** (`HistoryContext.messages`) | ❌ **不持久** | `__init__` 中 `self.messages = []`，无 `load_messages()` |
| **轮次计数** (`self._round`) | ❌ **不持久** | 硬编码 `= 0`，无 save/load |
| **活跃 agent 列表** | ✅ 持久 | `GroupChatState.load_active()` → `active_agents.json` |
| **Leader 名称** | ✅ 持久 | `GroupChatState.load_leader()` → `leader.txt` |
| **Agent 注册表** | ✅ 持久 | 从配置文件加载 |
| **会话日志** | ⚠️ 仅追加写 | `chat_log.txt` + `session.jsonl`，**不回读** |

### 根因链

```
engine = GroupChatEngine(config, provider, workspace)  # 进程启动时创建
  → HistoryContext(state=self._state)
    → self.messages = []           # ← 空列表，无恢复逻辑
  → self._round = 0               # ← 硬编码，无恢复逻辑

# 持久层只有 append-only 写入：
GroupChatState.save_message()
  → chat_log.txt (追加写)
  → session.jsonl (追加写)
  # 没有 load_messages()，从不回读
```

### 进程内确定性（为什么一致）

`history_to_messages()` 是纯函数，给定相同输入产生相同输出：
- `relevant_agents=None`（broadcast 模式下所有 agent 看全量历史）
- `agent_ranks` 从 `engine.registry` 静态配置计算（`broadcast_round._agent_ranks_cache`），确定性
- `max_chars` 从 `history_settings.json` 读取，不变
- `age_tool_log()` 是正则替换，确定性

### 跨进程不一致（为什么不持久）

Telegram bot 中 engine 是长驻单例（`self._groupchat_engine`），进程重启后：
1. `HistoryContext.messages` 重新初始化为空列表
2. `self._round` 重置为 0
3. `chat_log.txt` / `session.jsonl` 有记录但**不回读**
4. 所有 agent 从空白历史开始，之前的协作上下文完全丢失

## 备注

- **设计意图推测**：当前架构可能是"有状态长驻服务"模式（bot 进程常驻），历史靠内存保持。日志文件是审计用途而非恢复用途。
- **如果要实现跨进程持久**：需要在 `HistoryContext.__init__` 中从 `session.jsonl` 回放消息，并持久化 `_round`。但需注意 `maybe_compress()` 的 AI 摘要在回放时无法复现（LLM 输出不确定）。
- **`552e2ab` 的修改不受影响**：`age_tool_log` 是确定性正则，回放时结果一致。
