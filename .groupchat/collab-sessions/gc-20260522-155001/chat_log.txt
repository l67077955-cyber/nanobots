## 根因

DSML 特殊 token（`<>`）在**训练数据**中密集出现于工具调用场景，模型学到了"看到用户消息 → 偶尔输出 DSML 标记"的条件概率。当系统**静默注入**了 DSML 格式的上下文（即使对用户隐藏），模型在推理时会有非零概率**把训练分布中的内部格式泄漏到输出token流**——这叫 **format leakage**。

[Kirk]: ## 结论

这是 **DeepSeek 模型的已知问题**，不是你的代码或 prompt 导致的。模型有时会在普通文本输出中"泄漏"原始 DSML 工具调用标记，而不是通过标准的 `tool_calls` 字段返回。通过第三方 API 代理（NVIDIA、vLLM、Chutes 等）调用时概率更高。

## 关键发现

- **根因**：DeepSeek 内部用 DSML 格式表示工具调用，第三方代理的兼容层未能正确解析 DSML → OpenAI 格式，导致原始 token 泄漏到文本中
- **无效调用**：模型有时生成格式不完整或参数错误的 DSML 块，框架解析失败
- 社区广泛报告（NVIDIA 论坛、vLLM 论坛、GitHub issues），目前无完美修复

## 解决方案

| 方案 | 说明 |
|---|---|
| **用 DeepSeek 官方 API** | `api.deepseek.com` 兼容层最完善 |
| **启用 strict mode** | `base_url="https://api.deepseek.com/beta"` + `"strict": true` |
| **客户端过滤** | 正则清理残留的 `<｜｜DSML｜｜...>` 标记 |
| **换模型** | GPT-4o / Claude 等无此问题 |
