[Harper]: 记忆已命中，直接回答。

**因为轮询不走 tool_loop 是架构上的必然——不是疏忽，是时序和职责决定的。**

三条理由：

**1. 时序上 agent 已经停了**
`auto_recall_memories()` 在每轮群聊开始前执行（此时 agent 还没启动），`auto_store_memories()` 在每轮结束后执行（此时 agent 已停止）。tool_loop 只在 agent 活跃期间运行，轮询的执行窗口根本不在 tool_loop 的生命周期内。

**2. 这是系统行为，不是 agent 行为**
轮询是 `run_loop.py`（调度层）的责任，不是 agent（对话层）的责任。让调度层的后台任务去走 agent 的工具调用管线，等于让操作系统调用应用层的 GUI API——层级错了。

**3. 效率上不需要经过渲染管线**
tool_loop → engine.py → broadcast_view.py → Telegram 这条链路是为人类可读的工具调用结果设计的。轮询的存储/召回结果是机器数据（drawer_id、相似度分数），对用户没有阅读价值。直接写 ChromaDB + logger.info() 就够了。

Kirk 刚才的代码注释也写了 `# no LLM tool loop — direct function call`，就是这个意思。
