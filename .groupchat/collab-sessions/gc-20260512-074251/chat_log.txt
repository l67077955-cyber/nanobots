## Bug 1: `cannot access local variable 'PromptBuilder'`

**根本原因**: 在 `_on_callback()` 方法的 `rlog_dl:` handler（line ~460-490）中有局部 import：

```python
from nanobot.groupchat.history.prompt_builder import PromptBuilder
```

而在同一个巨大方法内的 `pre:` handler（line ~1100-1120）中也用了 `PromptBuilder.get_component_template(key)`。

由于这是单个超长方法（~1940行），Python 编译器看到该方法内任意一处出现 `from X import Y`（这本质上是局部赋值 `Y = ...`），就会把整个方法体中的 `Y` 标记为**局部变量**。所以当用户走另一条代码路径进入 `pre:` handler 时，那个局部的 `from ... import` 还没被执行到，于是抛出 UnboundLocalError。

**修复**: 在 `pre:` handler 前面加一行局部 import，或者在方法开头统一 import。

## Bug 2: `'list' object has no attribute 'items'`

**位置**: `ahp:` handler（agent hyperparams），大约 line 1036+

```python
elif data.startswith("ahp:"):
    parts = data.split(":", 2)
    a_name, key = parts[1], parts[2]
    agent = self._groupchat_engine.registry.get(a_name, {})
    agent_hp = agent.get("hyperparams") or {}
```

问题是：对于刚创建的 agent（没有显式设置过 hyperparams），`agent["hyperparams"]` 可能是缺失的 → `.get(...)` 返回 None → `{}` OK。但如果是旧版存储的数据结构不同，或者在某些情况下 registry entry 本身是个 list...
