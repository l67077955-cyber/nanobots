[Kirk]: ## 结论

ranked_base打断逻辑分布在 `mailbox.py`（权限判定+事件触发）和 `broadcast.py`（触发入口+打断后处理）两层，05-22~05-27期间完成了从基础rank注入到三个稳定性修复的完整演进。

## 关键发现

### 核心代码链（mailbox.py）

**1. 等级注入 — `set_ranks()`**
```
order = {"pawn": 0, "knight": 1, "bishop": 2, "queen": 3}
Leader = max(order.values()) + 1  # 永远最高
```

**2. 权限判定 — `_can_interrupt(sender, target)`**
```
return self._ranks.get(sender, 0) > self._ranks.get(target, 0)
```
- Leader 打断任何人 ✅
- 高rank打断低rank ✅
- 同rank互相打断 ❌（排队）
- 未知rank默认0（最低）

**3. 单目标打断 — `_try_interrupt(target, sender)`**
前置检查链：`target != sender` → `target in _busy_agents` → `_can_interrupt()` → `count < 3` → `event.set()`
- 每agent每轮最多被打断3次
- 被打断后count在broadcast主循环重置为0

**4. 全量打断 — `interrupt_busy_agents(sender)`**
- 用于 `target="All"` 场景（用户消息等高优先级）
- **不消耗** `_interrupt_counts` 配额
- 重置被中断agent的count为0
- sender="用户"时跳过rank检查（用户消息打断所有人）

**5. 触发入口（broadcast.py `_trigger_realtime_interrupts`）**
```
chatroom_send成功 → 
  target="All" → interrupt_busy_agents(sender)
  target=具体名 → _try_interrupt(target, sender)
```

**6. 打断后处理（broadcast.py 主循环）**
```
tool_loop返回 finish_reason="interrupted" →
  ① 清interrupt event（允许再次打断）
  ② 重置interrupt count为0
  ③ drain整个消息队列，取最新消息响应（LIFO语义）
  ④ 显示打断UI（带rank badge）
  ⑤ 保存已产出的partial content
```
