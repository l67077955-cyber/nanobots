[Kirk]: ## SillyTavern 最佳超参数设置（2026年）

### 核心结论

2026年范式已变：**从一堆参数微调 → 只调 Temperature + Min-p + DRY 三件套**，其余关闭。

---

### 🎯 角色扮演/对话推荐配置

| 参数 | 推荐值 | 说明 |
|---|---|---|
| **Temperature** | 1.0 – 1.3 | 对话创意性核心旋钮 |
| **Min-p** | 0.05 – 0.1 | 替代 top_k，动态过滤低概率 token |
| **Top-p** | 0.95 | 配合 min-p |
| **DRY Multiplier** | 0.8 | 最强反重复，dry_base=1.75, allowed_length=2 |
| **Repetition Penalty** | 1.1（起点） | 严重重复时提至 1.2–1.4 |
| **Rep Penalty Range** | 200 – 350 | 过高会惩罚 "the"、"and" 等常用词 |
| **XTC** | threshold 0.15, prob 0.5 | 可选，防相似表达循环 |
| **Top-k / Frequency / Presence** | 关闭 | 不需要 |

### 📐 模型作者官方推荐

- **Qwen 3.6**: temp 1.0, top_p 0.95, top_k 2000
- **Gemma 4**: temp 1.0, top_p 0.95, top_k 6400
- **DeepSeek V4-Pro**: temp 1.0, top_p 1.0（极简主义）
- **Llama 4**: temp 0.7, top_p 0.94, min_p 0.05

### ⚠️ 关键注意事项

1. **不要改采样器顺序** — 默认链：penalties → DRY → top_k → top_p → min_p → XTC → temperature → sample
2. **Min-p 过高（>0.1）反而加剧重复**，出现循环时先调低
3. **Rep Penalty Range 超 500 会破坏输出**
4. Temperature 在采样链最后应用，只影响采样方式不影响候选池

最简起点：`Temperature 1.0, Min-p 0.1, DRY 0.8, 其余全关` → 根据实际输出微调。

[Kirk]: ## 结论

`mailbox.py`（782行）是对话池的全部实现，包含 **ConversationPool**（槽位管理）和 **MailboxHub**（消息路由+中断）两个核心类。

## 关键发现

### ConversationPool — Per-Agent 独立信号量

| 特性 | 实现 |
|---|---|
| **容量模型** | 每个 agent 独立 `asyncio.Semaphore`，支持 `per_agent_capacity={agent: cap}` 或统一 `capacity=N` |
| **默认容量** | `max(len(agents) * 3, 1)` |
| **槽位消耗** | 发送者扣自己的池。`chatroom_send(to="All", 3人)` = 扣3槽 |
| **释放路径** | ① `release_unread(agent)` — wait不回复时归还所有pending发送者的槽 ② `mark_replied(agent, sender)` — 回复时归还1槽给sender |
| **用户优先级** | `allocate_user()` 强制从每个recipient扣1槽，期间 `_user_priority` event 阻塞所有agent发送 |
| **溢出设计** | `_available` 可变负数（用户消息强制扣减时，设计意图） |
| **超时** | `ALLOCATE_TIMEOUT = 15s`，超时自动归还已获取的槽 |

### MailboxHub — 消息路由 + 中断系统

| 特性 | 实现 |
|---|---|
| **消息投递** | `send()` 支持定向和广播，自动跳过sender，检查listener限制 |
| **wait机制** | 快速路径（队列非空立即返回）→ 阻塞等待（5s轮询）→ deadline自动延长（最多12次×5s=60s额外） |
| **死锁检测** | 全员waiting时 `_nudge_random_agent()` 随机注入系统消息打破僵局 |
| **中断层级** | pawn(0) < knight(1) < bishop(2) < queen(3)，Leader最高优先级；同级不可互相中断 |
| **中断限制** | 每agent每round最多3次agent间中断；用户消息中断不计入配额且重置计数器 |
| **expected_replies** | 追踪谁可能回复谁，用于wait deadline自动延长（防止忙agent被误判超时） |
| **listener限制** | `set_listener_restriction()` 可限制agent只接收特定sender的消息 |

### 数据流

```
chatroom_send → ConversationPool.allocate(sender, recipients)  [扣sender槽]
              → MailboxHub.send(sender, targets, content)       [投递+中断]
              → 每个recipient的 asyncio.Queue

wait() → MailboxHub.wait(agent, timeout)                       [5s轮询+自动延长]
       → ConversationPool.release_unread(agent)                [不回复→全还]
       → 或 ConversationPool.mark_replied(agent, sender)       [回复→还1槽]
```

### 关键设计决策

1. **Per-agent 而非全局池** — 防止单个agent垄断对话，每个agent独立预算
2. **用户消息强制扣recipient池** — 防止agent通过只接收用户消息绕过限制
3. **分级中断** — Leader可打断任何人，worker之间按rank层级控制，同级排队不互断
4. **deadline自动延长** — wait时如果对方还在忙（expected_replies追踪），自动延长最多60s，避免误判超时
5. **全员死锁nudge** — 检测到所有agent同时waiting时，随机选一个注入系统消息打破循环
