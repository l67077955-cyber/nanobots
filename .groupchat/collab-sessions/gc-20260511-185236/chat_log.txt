### 你看到的低 token 调用是路径 ①

`SmartFetchTool` 在 `chatroom_tools.py:434` 只检查 `len(raw_text) >= 50`，**没有上限检查**。只要网页返回了 ≥50 字符的内容，就会调 GLM 5.1 做提取。那些网站（gettyimages、bbc）反爬返回了短内容（590-843 chars），但仍然 ≥50，所以触发了提取。

### 是否有逻辑问题？

**路径 ① 有一个可以优化的点**：`SmartFetchTool` 对极短内容（50-500 chars）也调 AI 提取，浪费 token。可以加一个下限，比如 `len(raw_text) < 500` 时直接返回原文。

但路径 ② 和 ③ 的逻辑没有问题——阈值分别是 8,000 chars 和 40 条消息，不会在低 token 时触发。

`chatroom_tools.py:434`：

if not raw_text or len(raw_text) < 50:

只要网页返回 ≥50 字符就调 GLM 5.1 做提取。590 chars 的内容提取后可能也就 400 chars，**AI 处理成本远大于收益**。

### 建议修复

把下限从 50 提高到 **500-1000 chars**：

```python
# chatroom_tools.py:434
if not raw_text or len(raw_text) < 500:  # ← 从 50 改为 500
    return raw_result
```

理由：
- 500 chars 以下的内容，AI 提取能压缩的空间极小（prompt 本身就占几百 token）
- 反爬返回的空壳页面通常 <1000 chars，直接跳过更省
- 真正需要 AI 提取的长文章通常 >2000 chars
