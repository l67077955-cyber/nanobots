### 六大问题

**1. wing_code 是万能垃圾桶**
~40 个 drawer 是一次性 bug 调试记录（`glm51-low-token-xxx`、`timeout-chain-fix`、`summarize-enabled-bug`…），修完即废，永久占用空间稀释搜索精度。

**2. Knowledge Graph 零使用**
`kg_add/kg_query/kg_timeline/kg_invalidate` 从未调用。实体关系建模能力完全浪费。

**3. Tunnel（跨 wing 桥接）为零**
wing_code 和 wing_user 之间无任何连接。例：用户要发图 → debug skill 有 `send_photo_cli.py`，这个关联从未被记录。

**4. wing_user 有重复**
`hearthstone-patch-35-4-2` 和 `hearthstone-35-4-2-patch` 重复；`art-preferences` 和 `art-artist-preferences` 重叠。

**5. Diary 和 Hall 未使用**
agent 日记从未写过，hall 参数在 store 时被忽略，失去行为模式学习和知识分类能力。

**6. 协议遵守不彻底**
agent 仍经常跳过 memory_palace search 直接走 exec/read_file（prompt 工程问题，非工具问题）。

### 🔴 P0 — wing_code 大扫除
删除 ~40 个一次性调试 drawer，只保留架构决策、skill 清单、实用能力、工具配置等持久知识。搜索噪声降低 80%。

```
user → prefers → 极简输出

debug-skill → has_script → send_photo_cli.py
nanobot → has_bug → recall指定room返回空
```

### 🟡 P2 — 建立跨 wing Tunnel
```
wing_user/art-preferences ↔ wing_code/send-photo-capability
wing_user/user-behavior-fawei ↔ wing_user/preferences
```

### 🟢 P3 — 正确使用 Hall 分类
