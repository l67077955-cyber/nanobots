[Kirk]: 问题根因清楚了：**cloudflared 没有做持久化，进程一挂就断。** 当前是 `nohup` 裸跑，没有 systemd 管理、没有自动重启、没有监控。

两个层面的解决方案：

---

### 方案一：治标 — systemd 守护 + 自动重启（推荐先做）

把 cloudflared 和 SillyTavern 都注册为 systemd service，崩溃/重启后自动拉起：

```ini
# /etc/systemd/system/sillytavern.service
[Unit]
Description=SillyTavern
After=network.target

[Service]
Type=simple
WorkingDirectory=/root/SillyTavern
ExecStart=/usr/bin/node server.js --port 8090
Restart=always
RestartSec=5
Environment=HOME=/root

[Install]
WantedBy=multi-user.target
```

```ini
# /etc/systemd/system/cloudflared-tunnel.service
[Unit]
Description=Cloudflare Quick Tunnel
After=network.target sillytavern.service

[Service]
Type=simple
ExecStart=/usr/local/bin/cloudflared tunnel --url http://127.0.0.1:8090
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target
```

启用后 `systemctl enable --now` 两个服务，进程挂了自动重启。

---

### 方案二：治本 — 绑定域名做 Named Tunnel（彻底解决 URL 变化问题）

Quick Tunnel 每次重启 URL 都变，体验很差。Named Tunnel 绑定你自己的域名后：
- URL 固定（如 `tavern.yourdomain.com`）
- cloudflared 断线重连后域名不变
- 需要：一个域名 + Cloudflare 账号

[Kirk]: ## 结论

酒馆网页打不开的根因是 **cloudflared 进程没有持久化**——裸跑 nohup，崩溃或自动更新后进程消失，隧道断开。

## 关键发现

- **根因**：cloudflared 和 SillyTavern 都用 `nohup` 裸跑，无 systemd 管理、无自动重启、无监控
- **当前状态**：已手动重启，临时可用：`https://infringement-pediatric-reprint-con.trycloudflare.com/`
- **架构缺陷**：Quick Tunnel 每次重启 URL 都变，治标不治本

## 解决方案

| | 方案一（治标） | 方案二（治本） |
|---|---|---|
| 做法 | 写 systemd service，`Restart=always` 自动拉起 | 绑定域名做 Named Tunnel |
| 效果 | 进程挂了自动重启，减少中断 | URL 永久固定，断线重连不变 |
| 代价 | 改完即生效，5分钟 | 需要域名 + Cloudflare 账号 |
| 推荐度 | ⭐⭐⭐ 先做 | ⭐⭐⭐⭐⭐ 最终目标 |
