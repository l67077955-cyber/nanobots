用户说的没错。一条消息的逻辑确实很简单，四个要素就够了：

**发谁 → 谁发 → 检查权限 → 幻觉fallback**

现在的实现把这四件事拆得太散：
- `chatroom_send` 管"发谁+谁发"
- `Self/Final`（现 `Output`）管"幻觉fallback"
- 权限检查散布在 broadcast.py 多处
- mailbox.send() 和 engine._send() 两条路径并行

实际上可以合并成一个统一的 `send_message(target, content, source)` 入口，内部做：
1. target=All/AgentName → mailbox.send()
2. target=None/local → engine._send()（本地展示）
3. 权限检查作为中间件

这样就不需要两套路由逻辑了。不过既然已经改成了 `Output [N]`，命名至少对了——剩下的重构是架构层面的决定，不是命名能解决的。

[Kirk]: ## 结论

用户的四步模型（sender → target → permission → fallback）是正确的消息路由抽象。当前系统的问题是**把"展示"和"路由"混在一起**，Output [N] 假装是消息但没有 target，和正式消息视觉上无法区分。

## 关键发现

- 当前消息有两条完全不同的代码路径（chatroom_send vs engine._send），但 UI 上看起来像同一种东西
- Output [N] 缺少 target 语义——它是"agent 说了话但不知道说给谁"的产物，不是消息
- 权限检查层完全缺失，任何 agent 都能发给任何人
- 幻觉 fallback 的展示应该和正式消息**视觉上明确区分**，不能让用户误以为已被路由

## 备注

改进方向：有 target → 正常路由 + 权限检查；无 target → 标注为本地输出，视觉上降级处理（比如灰色、缩进、不同前缀）。
