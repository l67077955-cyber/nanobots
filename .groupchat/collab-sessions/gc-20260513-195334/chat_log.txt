## 审查结果：发现问题 × 2

### 问题 1：【Critical】`all_tools_used` 跨周期累积导致虚假命中

**位置**: `broadcast.py:820`

```python
all_tools_used.extend(result.tools_used or [])
```

这行在每个 cycle 都追加工具名。如果一个 worker 在第1周期用了 `web_search`，第2周期用了 `memory_palace.store`，那么当 leader 在第3周期调 `end_discussion` 时，传给 `synthesis_quality_check` 的 `tools_used` 会是 `["web_search", "memory_palace"]`。

后果：
- **Tier 4a** (`has_other_data_tools`) → `True`（因为有 web_search），所以 memory_palace-only-thin-text 不会被拦截 —— **漏报**
- **Tier 4b** → `True`（同样理由），但如果 leader 根本没用到这些工具的数据，也不该被放过

**本质问题**: `all_tools_used` 是整个会话的工具清单，而 delivery gate 关心的是**本周期内使用的工具及其产出的数据是否体现在文本中**。混在一起会让判断失真。

**修复建议**: 
- Option A: 改为只传当前周期的工具集（`result.tools_used`）
- Option B: 保持累加但增加时间衰减——比如标记哪些工具有"新鲜产出"，只有新鲜产出才参与门控

---

### 问题 2：【Medium】Tier 4a regex pattern over-inclusive

**位置**: `component_manager.py:117`

```python
or bool(re.search(r'地址|address|street|ave|blvd|road|drive', text, re.I))
```

这条匹配太宽泛了。一段关于交通规划的讨论也可能出现 "road"、"drive"。更准确的做法是用上下文锚定——例如匹配带数字的模式组合：

```python
# Better: address-like patterns require street NUMBER + road TYPE
re.search(r'\d+\s+(?:[\w\s]+)?(?:Street|St\.?|Avenue|Ave\.?|Road|Rd\.?|Drive|Dr\.?)', text, re.I)
```

不过考虑到这只是辅助启发式而不是判决依据（后面还有长度检查和结构检查兜底），影响有限。
