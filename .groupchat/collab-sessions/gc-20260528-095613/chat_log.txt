## 结论：不能，而且没必要

**轮询不走工具调用体系**，它在 `run_loop.py:133` 硬编码调用 `auto_recall_memories()`，发生在所有 agent 创建和广播之前。这不是 agent 触发的，是群聊引擎层的行为。

### 为什么看不到搜索关键词
- **自动轮询**：`run_loop.py` 里的 `auto_recall_memories()` 调用 → ChromaDB 语义搜索 → 结果直接注入系统提示词。整个过程在 agent 可见范围之外，Telegram 里没有任何显示
- **手动存储/检索**（agent调用的 `memory_palace(store/search)`）：这个会出现在工具调用记录里，但只显示参数和返回值摘要，不显示完整关键词和存储内容

### 想看关键词怎么办？
两个方案：

**方案A（最简单）**：在 `_generate_wing_queries()` 加一行日志打印生成的 JSON
```python
logger.info("wing queries generated: %s", queries)
```
这样每次轮询都能从日志看到 nano 生成了什么关键词。

**方案B（可视化）**：把轮询结果通过 `chatroom_send` 广播给群聊
```python
# _auto_recall.py 尾部加一行
await engine.broadcast(f"[记忆检索] wing_code关键词: {queries['wing_code']}")
```
但这会污染聊天流，不建议。

### memory_palace store/search Telegram不可见的原因
这是架构设计决定的——自动轮询是后台服务行为，不是 agent 的工具调用。只有 agent **主动调用** `memory_palace(store)` / `memory_palace(search)` 时才会出现在 Telegram 的工具调用记录里。而自动存储/召回走的完全是另一条路径（`_auto_memory.py` / `_auto_recall.py`），绕过了 agent loop。
