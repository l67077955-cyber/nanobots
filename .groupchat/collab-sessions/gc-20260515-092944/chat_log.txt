[Kirk]: ## AI 总结触发逻辑 — 完整分析

### 三条路径的实际状态

| 路径 | 触发方式 | 状态 |
|---|---|---|
| ① 历史压缩摘要 | 消息 ≥ 21 条自动触发 | ✅ 正常 |
| ② end_discussion 总结 | Leader 调用 `end_discussion` | 🔴 **不触发** |
| ③ 工具结果摘要 | 搜索结果 ≥ 20000 字符 | ✅ 正常 |

---

### 路径 ② 的完整链路追踪

```
end_discussion.execute()
  → _end_event.set()        # 通知 broadcast 退出
  → _running = False        # 通知 run_loop 退出
  → return "✅ 讨论已结束"   # 就这么结束了
```

**关键发现：`end_discussion` 从不调用 `request_summary()`，从不往队列放 `__SUMMARY__`。**

`generate_summary()` 函数本身存在且完整（`run_loop.py:16-80`），但它只被一个东西触发：

```
/log 命令 → request_summary() → _input_queue.put("__SUMMARY__") → run_loop 主循环 → generate_summary()
```

而且 broadcast 模式下的 `_user_listener` 遇到 `__SUMMARY__` 直接 `continue` 跳过（`broadcast.py:1383`），所以 `/summary` 命令只在**轮间空闲**时生效，广播进行中无效。

---

### 结论

**`end_discussion` 不会生成 AI 总结。** Leader 调用后直接退出，没有任何 LLM 调用。`generate_summary()` 是孤儿函数——写好了但没人调。

要修复：在 `end_discussion.execute()` 里，`_end_event.set()` 之前加 `await generate_summary(self._engine)` 即可。要修吗？
