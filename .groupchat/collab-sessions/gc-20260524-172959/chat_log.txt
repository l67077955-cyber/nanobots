[Kirk]: ## 结论

tool_loop.py 的重复检测有**两层机制**，但都存在盲区。用户看到的重复消息（同一段话重复5次）暴露了核心缺陷：**退化重复检测完全依赖标点分割，无标点的大段重复文本无法被捕获**。

## 关键发现

### 层1：工具调用去重（L519-561）— 正常
- `_DEDUP_TOOLS` 集合 + `_seen_calls` 缓存 + `_batch_dedup_keys` 批量内去重
- **只防工具重复调用，不防文本输出重复**

### 层2：退化重复检测（L458-477）— 有缺陷
- `_has_contiguous_repeat()` 用 `[\n。！？.!?\u3002]` 分割后检测连续≥3次相同 segment
- **缺陷1**：只检测连续重复，A-B-A-B 间隔模式漏检
- **缺陷2**：`min_repeat=3`，2次重复不触发
- **缺陷3（关键）**：无标点分隔的大段重复文本被当作单个 segment，检测完全失效
- **缺陷4**：微小差异（空格/标点变化）导致匹配失败

### 工具结果注入流程（完整）
1. LLM 返回 tool_calls → L512-517 构建 assistant message（含 tool_calls）append 到 messages
2. Phase 1（L519-580）：逐个检查去重/权限，重复的直接 append tool role message 带 `[DUPLICATE]` 标记
3. Phase 2（L594-609）：`asyncio.gather` 并行执行非重复工具
4. Phase 3（L611-674）：逐个处理结果，`process_tool_result()` 格式化后 append tool role message

## 备注

建议改进：增加**滑动窗口字符级 n-gram 重复检测**作为补充，不依赖标点分割。例如检测连续 50+ 字符的子串在全文中出现≥3次即判定重复。
