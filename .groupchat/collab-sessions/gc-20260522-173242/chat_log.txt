[Kirk]: ## 结论

配置仓库（`~/.nanobot`）应该合并进代码仓库（`nanobot-src`）。当前分裂是历史遗留，不是合理设计——版本标签要打两套、pre-push hook 要跨仓库检查、路径硬编码散落 29 个文件没人统一管，这些都是分裂的症状。

## 关键发现

**现状：**
- `nanobot-src`：1687 commits，代码仓库，dev 分支
- `~/.nanobot`：24 commits，配置仓库，master 分支
- 29 个文件、~100 处硬编码 `Path.home() / ".nanobot"`，**没有统一路径入口**（`paths.py` 存在但大部分模块没用它）

**配置仓库实际追踪的核心内容：**
- `agents/` — 各 agent 的 character/config
- `prompts/` — 系统提示词
- `config.json`, `providers_models.json`, `hyperparams.json` 等全局配置
- `cron/jobs.json`, `skills/`, `memory/`, `active_agents.json`, `groups.json` 等

**运行时垃圾（不应进任何 git）：**
- `request_logs/` 883MB、`workspace/` 336MB、`mempalace/`、`collab-sessions/`、`media/`、`logs/`

## 推荐方案（三步走）

| 步骤 | 内容 | 改动量 |
|------|------|--------|
| ① 引入 `NANOBOT_HOME` | `paths.py` 统一所有路径派生，fallback `~/.nanobot` | 29 文件，每处替换为函数调用 |
| ② 配置迁入 monorepo | 核心配置文件移入 `nanobot-src/config/` | git mv + 路径调整 |
| ③ 运行时分离 | workspace/、mempalace/ 等继续留在 `~/.nanobot/` 不进 git | 只改 .gitignore |

**零改动过渡方案（不想动代码时）：**
- `~/.nanobot` 的配置文件 symlink 到 `nanobot-src/config/`
- 代码仓库 git 追踪 `config/`，运行时通过 symlink 读
- 缺点：不解决路径混乱的根本问题

## 备注

- 配置仓库 .git 有 153M，大量是 .bak 文件，合并前建议清理
- 配置仓库才 24 commits，合并历史成本极低
- 要动手合并的话可以直接写迁移脚本
