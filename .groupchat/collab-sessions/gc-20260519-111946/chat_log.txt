[Kirk]: ## 结论

当前 loader.py 有三个盲区导致"非标准 skill"不可见：无 SKILL.md 的目录被跳过、格式错误的 SKILL.md 导致 metadata 全部丢失、孤立脚本永远不会被发现。修复方向是**目录驱动发现 + config 覆盖 + SKILL.md 可选**。

## 关键发现

**盲区1：无 SKILL.md = 不存在**（`loader.py:125-126, 135-136`）
```python
skill_file = skill_dir / "SKILL.md"
if skill_file.exists():  # ← 唯一准入条件
    skills.append(...)
```
纯脚本目录（任务留存的自动化代码）直接被跳过，即使里面有可执行的 `.py` 文件。

**盲区2：格式错误 = 全盲**（`loader.py:460-490`）
`get_skill_metadata()` 要求首行必须是 `---`，否则返回 `None`。后果链：
- `description` 为空 → summary 只显示名称无说明
- `always` 无法读取 → 不会被 always-on 选中
- `requires` 无法读取 → 不会被标记 unavailable（反而可能被误认为可用）

**盲区3：孤立脚本永远不发现**（`loader.py:420-423`）
`_discover_undocumented_scripts()` 只遍历 `list_skills()` 返回的 skill 目录。不在任何 skill 目录下的脚本（比如 `workspace/scripts/auto_cleanup.py`）永远不会出现在提示词中。

**当前 workspace 下无实际非标准 skill**（workspace 目录运行时传入，代码库中不存在），但设计缺陷是真实的。

## 修复方案

**目录驱动发现**（改 `list_skills()`）：
```python
# 现在：SKILL.md.exists() → yield
# 改为：entry.is_dir() → yield {name, dir, has_doc, has_scripts}
```

**config 覆盖 metadata**（改 `get_skill_metadata()`）：
```
优先级：config/skills.yaml[name] > SKILL.md frontmatter > default
```

**SKILL.md 完全可选**：无文档的脚本目录从 config 拿 description，有文档的照常读取。约 40 行改动，零接口变更，9 个调用方透明。
