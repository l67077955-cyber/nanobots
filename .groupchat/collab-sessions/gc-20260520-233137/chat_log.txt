## 问题定位

**守卫链路**: `shell.py:_guard_command()` → `security/network.py:contains_internal_url()` → `validate_url_target()`

核心代码在 `contains_internal_url`（`/root/nanobot-src/nanobot/security/network.py:97-104`）：

```python
def contains_internal_url(command: str) -> bool:
    for m in _URL_RE.finditer(command):
        url = m.group(0)
        ok, _ = validate_url_target(url)
        if not ok:          # ← 问题在这行
            return True     # ← DNS解析失败也阻挡
    return False
```

`validate_url_target` 返回 `not ok` 有两种情况：
1. ✅ **真阳性**: URL 解析到私有 IP（`127.0.0.1`、`10.x.x.x`、`192.168.x.x` 等）→ **应该拦截**
2. ❌ **假阳性**: URL 无法解析/DNS失败（如你打的 `http://loca` 拼写错误、临时网络故障）→ **不该拦截**

**你那个例子的完整路径**:
```
curl -s http://loca
  → regex 匹配到 http://loca
  → urlparse → hostname="loca"  
  → socket.getaddrinfo("loca") 失败 → gaierror
  → validate_url_target 返回 (False, "Cannot resolve hostname: loca")
  → contains_internal_url 返回 True → BLOCKED ❌
```

---

## 优化方案

原则上：**exec 已经有完整的 bash 权限，在这个前提下单纯封 curl 到 localhost 是安全剧场**。但最小改动方案如下：

**改动点 — `contains_internal_url` 区分 DNS 失败 vs 真实私有 IP**：

```python
def contains_internal_url(command: str) -> bool:
    """Return True if the command contains a URL targeting an internal/private address."""
    for m in _URL_RE.finditer(command):
        url = m.group(0)
        ok, msg = validate_url_target(url)
        if not ok and "private/internal" in msg:   # ← 只拦截确认私有IP的
            return True
        # DNS失败、拼写错误等 → 放行（命令本身会失败，不需要guard挡）
    return False
```

这样 `curl -s http://loca` → DNS失败 → 放行（因为不是 "private/internal" 错误）。

如果要更激进（我认为在 exec 权限下合理）：

```python
# 直接移除 shell.py 中的网络检查
# _guard_command 中删掉以下两行：
# from nanobot.security.network import contains_internal_url
# if contains_internal_url(cmd): ...
```
