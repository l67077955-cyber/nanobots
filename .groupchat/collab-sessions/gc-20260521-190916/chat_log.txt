[Harper]: 明白，先分析排版问题，隧道等着一块修。

**mario.html 排版分析：**

```
┌─────────────────────────────┐
│  #info (操作提示, 白色文字)    │   ← top
├─────────────────────────────┤
│                             │
│     Canvas (512×480)        │   ← image-rendering:pixelated
│     max-width:100vw          │     max-height:calc(100dvh - 100px)
│                             │
├─────────────────────────────┤
│  ◀ ▶          R  JUMP       │   ← position:fixed; bottom:0
│  #controls (触控按钮)        │
└─────────────────────────────┘
```

**发现的问题：**

1. **body 用了 `justify-content:flex-start`** → 内容顶对齐，大屏下方大片黑底空着，不美观
2. **controls 固定底部** 且 `z-index:10`，但触控按钮在 canvas 之上，小屏手机 canvas 底部可能被按钮遮挡内容（游戏的地面层）
3. **canvas 的 object-fit:contain** 在宽屏手机上左右留黑边，但游戏是横向卷轴，合理的
4. **info 文字太小** `font:12px monospace`，触屏手机上不易读

**game.html 问题：**
- 已修复缺少 `max-width/max-height` 的问题
- 但和 mario.html 是两个独立的游戏实现，画面风格不统一

**index.html（pygbag 版）问题：**
- 加载极慢（下载 Python WASM runtime ~MB 级）
- 加载界面 UI 简陋
- 已修复 background #111

核心问题：用户大概率打开的是主页（pygbag）→ 加载慢 + loading 界面丑。或者手机打开 game.html（非触屏版）→ canvas 溢出。

我来建议最优解：**把根路径切到 mario.html（触屏版）**，pygbag 版留着当备选。这样用户打开主页直接能玩，排版也最完善。

Kirk，你觉得这个方案行不行？行的话我直接改 index.html 为跳转到 mario.html，然后一起修 tunnel。
