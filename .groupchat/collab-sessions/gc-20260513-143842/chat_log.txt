[Harper]: Kirk，我已读完完整流程。根因不是少调了一个函数——是**生命周期设计缺口**。

---

## 根因分析

```
EndDiscussionTool 承诺 "进入总结阶段"
└→ 实际执行：
   ├→ _end_event.set()        ← 正确（sentinel检测→cancel其他agent）
   ├→ _leader_end_reason = x  ← 正确（记录原因）
   └→ _running = False        ← ??? 跳过生命周期直接杀循环
```

**架构缺失**：讨论生命周期只有2个状态 `[输入 → 广播轮次]`，缺少第3状态 `[合成总结]`。`generate_summary()` 存在但只能通过 `__SUMMARY__` 队列触发——而这条路在广播模式中被 `continue` 跳过了。

**补丁 vs 修复**：补丁是在某处加个 `if` 调用 generate_summary。修复是为生命周期增加合成阶段。

---

## 修复方案（3个文件，3行核心改动）

**目标**：新增生命周期状态 `Synthesis Phase`，在 broadcast_round 返回后、run_loop 退出前触发。

| 文件 | 改动 | 目的 |
|---|---|---|
| `engine.py:296` | `self._leader_ended_discussion = False` | 新增生命周期状态变量 |
| `chatroom_tools.py:1101` | `self._engine._leader_ended_discussion = True` | 将状态从"讨论"切换到"合成" |
| `run_loop.py:113-122` | `if engine._leader_ended_discussion: await generate_summary(engine); break` | 合成阶段——在循环退出前执行 |

不需要改 `broadcast.py`——它只负责广播轮次，生命周期由 `run_loop` 管理。这正是"关注分离"。

### 具体流程修复后

```
Leader calls end_discussion()
└→ EndDiscussionTool: _ended=true, _running=false, event.set()
└→ broadcast_round: sentinel fires, cancel non-leader, 正常返回
└→ run_loop 检测 _leader_ended_discussion
   └→ SYNTHESIS PHASE: generate_summary(engine)     ← 新增！
      ├→ 用第一个活跃agent的模型 + 完整历史
      ├→ 输出: 核心观点 / 分歧点 / 初步结论
      └→ break → while循环退出 → finally清理
```

[Harper]: 找到根因了。

**总结确实发生了**——是Leader在最后一轮tool_loop输出的content（"进展 [3]"）。但质量差是因为**Leader hint中关于总结的指令太模糊**：

```
当前指令（broadcast.py:560-568）：
"在最终文字回复中整合所有发现，给出完整答案"
"你的最终文字回复就是给用户的答案，要完整、结构化"
```

对比 `generate_summary()` 的prompt（run_loop.py:35-39）：
```
"你是一个讨论总结专家。"
"请输出简洁总结：1)核心观点 2)分歧点 3)初步结论"
```

`generate_summary()` 给了3个明确维度，但**它从来没被调用过**。Leader的hint只说"完整、结构化"——太抽象，导致Leader自由发挥，质量不稳定。

---

## 修复方案

**只改一个文件**：`broadcast.py` 第560-568行，把模糊的"完整、结构化"替换为具体的总结模板。

```python
# 改前
f"6. 信息充分后，先完成以下两步，再调用 end_discussion()：\n"
f"   a. 在最终文字回复中整合所有发现，给出完整答案\n"
...
f"- 你的最终文字回复就是给用户的答案，要完整、结构化\n"

# 改后
f"6. 信息充分后，先完成以下两步，再调用 end_discussion()：\n"
f"   a. 输出结构化总结，格式如下：\n"
f"      ## 结论\n"
f"      （直接回答用户问题的核心结论）\n\n"
f"      ## 关键发现\n"
f"      （讨论中确认的关键事实、数据、来源）\n\n"
f"      ## 分歧与解决\n"
f"      （如有不同观点，说明最终如何收敛）\n\n"
f"      ## 后续建议\n"
f"      （可选：下一步可做的改进或延伸方向）\n"
```

这样Leader在最后一轮就知道**具体要输出什么结构**，而不是自由发挥。
