[Kirk]: `.gitignore` 的作用：**告诉 Git 哪些文件/目录不要跟踪**。

## 为什么需要它

1. **避免污染仓库** — 编译产物（`dist/`、`build/`）、缓存（`__pycache__/`）、虚拟环境（`.venv/`）不该进版本控制
2. **保护敏感信息** — `.env` 含密钥/Token，提交到仓库 = 泄露
3. **减小仓库体积** — 二进制文件、日志（`botpy.log`）每次 commit 都会膨胀历史
4. **避免冲突** — 每个开发者的本地配置不同（IDE 设置、OS 文件如 `.DS_Store`），不跟踪就不会冲突

## 当前仓库的 gitignore 覆盖了什么

| 类别 | 规则 | 防什么 |
|---|---|---|
| Python 垃圾 | `__pycache__/`、`*.pyc`、`*.pyo` | 字节码缓存 |
| 环境 | `.venv/`、`.env` | 虚拟环境 + 密钥 |
| 构建产物 | `dist/`、`build/`、`*.egg-info/` | 打包输出 |
| 测试缓存 | `.pytest_cache/` | pytest 缓存 |
| 锁文件 | `poetry.lock`、`uv.lock` | 避免锁文件冲突 |
| 编辑器/OS | `.DS_Store`、`nano.*.save` | 系统垃圾 |
| 数据库 | `memory_palace/` | 本地 ChromaDB 实例 |

**一句话：gitignore 是仓库的"过滤器"，只让有意义的代码进版本控制。**

---

**`.worktrees/`** — `git worktree` 会生成独立的 `.git/worktrees/` 元数据。不 ignore 的话，并行开多个工作树时仓库全乱。

**`.assets` / `.docs`** — 没有前缀 `*/`，意味着只忽略根目录下的这两个文件/目录。它们是**编译缓存**：`.assets` 存处理过的图片/资源，`.docs` 存生成的文档 HTML。不 ignore → 每次 build 刷一堆二进制文件进 diff。

**`.env`** — 这条最硬。项目依赖 20+ 个 API（LiteLLM、DingTalk、Telegram、Slack、QQ 机器人...），`.env` 存所有密钥。**漏一次 = 全站密钥暴露**。

**`__pycache__/` / `*.pyc`** — Python 自动生成。巨量文件，不 ignore 的话每次 import 后 `git status` 全是红色。

**`.venv/` / `venv/`** — 虚拟环境，几百 MB 的三方库。谁 push 这个谁被骂。

**`dist/` / `build/` / `*.egg-info/`** — `pip install -e .` / `hatch build` 的产物。提交打包产物 = 把 `.tar.gz` 放进历史。

**`poetry.lock` / `uv.lock`** — 有意思。`pyproject.toml` 里没用 poetry 也没用 uv，但这俩锁文件**如果**出现过就会被跟踪。ignore 意味着 "这项目不用 lockfile 锁版本"——走宽松依赖。

**`.pytest_cache/`** — pytest 的 AST 缓存，测试跑一次变一次。

**`botpy.log`** — 项目用了 `qq-botpy`（见 pyproject.toml 依赖），这是 QQ 机器人的运行时日志。每次连接都追加，不 ignore → 每个 commit 日志都在长大。

**`nano.*.save`** — 有人用 nano 编辑文件后按 `^O` 保存，nano 会生成 `.save` 备份。这条是**脏数据防御**——防手滑提交编辑器自动备份。
