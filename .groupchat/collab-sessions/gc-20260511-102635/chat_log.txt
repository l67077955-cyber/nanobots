### 🏛️ 三层架构总览

#### L1 — 逐结果截断（必走路径）
```
result_processor.process_tool_result()
├── normalize(bytes/dict/list→str, multimodal放行)
├── truncate(head_tail / head_only, per-tool上限来自settings)
│   ├── exec      → head_tail @ exec_max_chars(default?)
│   ├── web_fetch → head_only @ web_fetch_max_chars
│   ├── web_search→ head_only @ web_search_max_chars
│   └── other     → head_tail @ tool_result_max_chars(=20k)
└── persist(被截断的全量落盘到/tmp/nanobot/tool_storage/)
```
✅ **无条件执行，零延迟开销**

#### L2 — LLM语义压缩（可选增强）
```
summarizer.summarize_tool_output(output_str, tool_name, ctx_query=None)
├── guard: !hs.summarize_enabled() → return raw          ← settings控制总开关
├── guard: len(raw) ≤ hs.summarize_threshold() → return raw ← default?
├── build prompt: "精简下面{tool_name}的输出..." 
├── call LLM(model=hs.summarize_model(), temperature=0, max_out=hs.summarize_max_output_chars())
├── validate: summary_len ≥ input_len × ratio? → fallback截断头500字符
└── return compressed_string || truncated_head(500chars)
```
🔬 **仅在单个工具结果超大时才激活，节省的是跨工具的累积空间**

#### L3 — 整轮对话压缩重建（粗粒度兜底）
```
HistoryContext.__init__(messages[], ..., max_context_length=N)
                                    ↑ hard cap防止无限膨胀
                                    
HistoryContext.maybe_compress()
├── calc total_char = Σ len(msg.content) for each msg
├── if total_char > max_context_length × COMPRESS_RATIO_THRESHOLD(?):
│   │   （接近极限就开始压）
│   └── rebuild messages[]:
│       ├── keep system prompts untouched ✓
│       ├── early rounds → replace with generated summaries ↓↓↓↓
│       │   Prompt template大致为："简洁概括这段对话的核心事实和决定"
│       └── recent rounds → keep verbatim ✓
└── atomic swap: self.messages = new_list (线程安全)

HistoryContext.format_as_string()
└── render whole context as flat string for orchestration consumption
```
🔄 **异步触发，Engine在每条消息追加后调用_maybe_compress_history()**

---

### ✂️ 两条独立的Pruning支线

**Path A — tool_loop.prune_messages()**
- trigger: iteration > 1（多轮函数调用场景）
- target: remove old assistant+tool pairs but keep latest ones + system header intact
- scope: read-only view for LLM call, doesn't mutate source list

**Path B — broadcast.prune_conversation_tail()**
- trigger: agent wakes up due to teammate message in broadcast mode  
- rule: keep last CONV_KEEP_TURNS (=6) triplets of user-assistant-user exchange  
- purpose: prevent infinite accumulation across many sleep-wake cycles  

---

### 💭 Key Observations

1️⃣ **三段互补但不重叠**: L1(L2)→L3构成漏斗——细粒度的按结果处理在前，粗粒度的整轮压缩在后兜底。不会双重压缩同一个东西。

2️⃣ **Settings是所有阀门的源头**: history_settings模块暴露的函数名就是配置项命名规范——summarize_enabled/threshold/model/max_input/output_chars等等。想调整行为只需动这里。

3️⃣ **Prompt模板藏在context.py里**: summarizer用的是固定hardcode提示词（"精简下面的XXX输出"）；而HistoryContext的重建prompt也在类定义中内联维护。

4️⃣ **缺失环节**: 目前没看到显式的embedding+RAG召回型上下文管理——纯靠滑动窗口+暴力压缩实现长程记忆。
