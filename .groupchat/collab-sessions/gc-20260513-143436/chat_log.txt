**结论：不存在独立的"让leader生成结论的后置阶段"。**

`end_discussion` → `EndDiscussionTool.execute()` (chatroom_tools.py:1096)：
1. `self._end_event.set()` — notify sentinel coroutine
2. `self._engine._running = False` — kill switch

然后在 broadcast.py:1136‑1138：
```python
if _leader_ended_discussion:
    break   # ← immediate exit from round loop, no post-processing
```

**关键洞察**：「结论生成」嵌入了 Leader **最后那次 tool_loop invocation** —— hint(broadcast.py:560‑564)明确规定三步都在同一轮完成：

```
Step-a: final reply with complete answer      ← "结论"
Step-b: memory_palace store                   ← "存档"
Step-c: end_discussion                        ← "关门"
```

没有任何异步的 synthesis/conclusion stage。Leader在自己最后一个 iteration 的输出(content字段)就是最终的总结文本——直接被当作这一轮的输出展示出去。

唯一的例外是 Engine.request_summary(`__SUMMARY__`)路径(run_loop.py:19)，但那只在非广播模式的简化场景下走；广播模式下这条分支被 skip(你在前面看到的 `if msg=="__SUMMARY__": continue`)。

所以你说的没错，「应该有」，但实际上架构没这么做——它是把结论责任压给了 Leader **在关门前的那一轮输出**来完成。

[Kirk]: **问题定位：`end_discussion` 后缺少 synthesis 阶段**

调用链中 `end_discussion` → `_end_event.set()` → broadcast break → run_loop 退出，中间没有任何总结生成逻辑。

具体断裂点：
- `generate_summary()` (run_loop.py:19) 只响应 `__SUMMARY__` 队列消息，但 `EndDiscussionTool` 走的是 `_end_event` 路径，两条路径互不相通
- `_on_round_done` 回调只停 typing，无 synthesis
- Leader 的"结论"只是 tool_loop 最后一次迭代的 content 输出，不是独立阶段

**修复方向：** 在 `EndDiscussionTool.execute()` 中，`_end_event.set()` 之前（或 broadcast_round break 之后），触发 `generate_summary(engine)` 或等价的 synthesis 逻辑。
