# CS基础选择题 · 冲刺速记

## 一、操作系统

**进程与线程：**
- 进程是资源分配最小单位，线程是CPU调度最小单位
- 线程共享：代码段、数据段、堆、打开的文件描述符
- 线程私有：栈、寄存器、程序计数器、线程ID
- 进程通信方式（快→慢）：**共享内存 > 管道(pipe) > 消息队列 > 信号量 > Socket**
- 管道：半双工，只能用于亲缘关系进程（匿名管道）；命名管道可用于任意进程
- 信号：异步，不能传递复杂数据

**进程调度：**
- FCFS：非抢占，平均等待时间最长
- SJF：平均等待时间最短，但可能**饥饿**
- SRTF：SJF的抢占版本
- RR（时间片轮转）：时间片太大退化为FCFS，太小上下文切换开销大
- 优先级调度：可能饥饿，解决方法：**老化(aging)**
- 多级反馈队列：综合以上优点，现代OS常用思路

**死锁：**
- 四个必要条件：互斥、持有并等待、不剥夺、循环等待
- 预防：破坏任一条件即可
- 避免：**银行家算法**（Dijkstra）
- 检测：资源分配图 + 死锁定理
- 安全状态 ≠ 无死锁，不安全状态 → 可能死锁

**内存管理：**
- 虚拟内存：逻辑地址→物理地址，映射单位是**页(page)**
- 页表：存放在内存中，TLB加速页表查找
- 页面置换算法：
  - OPT（最优）：理论最优，不可实现
  - LRU（最近最少使用）：近似OPT，实现开销大
  - Clock（时钟算法）：LRU的近似，用引用位
  - FIFO：**唯一可能产生Belady异常**的算法（分配更多帧反而缺页更多）
- 抖动(thrashing)：进程频繁缺页，CPU利用率骤降，解决：减少并发进程数

**文件系统：**
- 超级块：存储文件系统元信息（块大小、inode数量等）
- inode：存储文件属性+数据块指针（不存文件名！）
- 目录项：文件名 → inode号的映射
- 硬链接：共享inode，inode引用计数+1，不能跨文件系统，不能链接目录
- 软链接(符号链接)：独立inode，存储目标路径字符串，可跨文件系统

## 二、数据结构与算法

**排序算法（必考）：**

| 算法 | 平均 | 最坏 | 空间 | 稳定 |
|------|------|------|------|------|
| 冒泡 | O(n²) | O(n²) | O(1) | ✅ |
| 插入 | O(n²) | O(n²) | O(1) | ✅ |
| 选择 | O(n²) | O(n²) | O(1) | ❌ |
| 归并 | O(nlogn) | O(nlogn) | O(n) | ✅ |
| 快排 | O(nlogn) | O(n²) | O(logn) | ❌ |
| 堆排 | O(nlogn) | O(nlogn) | O(1) | ❌ |
| 希尔 | O(n^1.3) | O(n²) | O(1) | ❌ |
| 计数 | O(n+k) | O(n+k) | O(k) | ✅ |
| 基数 | O(d(n+k)) | O(d(n+k)) | O(n+k) | ✅ |

- **稳定排序**：冒泡、插入、归并、计数、基数
- **不稳定排序**：选择、快排、堆排、希尔
- n较小时（<50）：插入排序最快
- 基本有序时：插入排序最快
- 快排最坏情况：已排序/逆序，每次选到最值做pivot

**树：**
- 二叉搜索树查找/插入/删除：平均O(logn)，最坏O(n)（退化为链表）
- AVL树：严格平衡（|左右子树高度差|≤1），查找O(logn)，旋转多
- 红黑树：近似平衡，插入/删除旋转少，查找O(logn)，Java TreeMap/HashMap底层
- B树：多路搜索树，每个节点存key+数据，适合磁盘读取
- **B+树**：数据全在叶子节点，叶子链表串联，范围查询快，**数据库索引首选**
- 哈夫曼树：WPL最小的二叉树，用于压缩编码，没有度为1的节点

**图：**
- BFS：队列，求无权最短路径
- DFS：栈/递归，拓扑排序、连通分量
- Dijkstra：单源最短路径，**不能处理负权边**
- Floyd：全源最短路径，O(n³)，可处理负权边（不能有负权环）
- 最小生成树：Kruskal（边排序+并查集）/ Prim（从点扩展）
- 拓扑排序：有向无环图(DAG)，DFS后序逆序 / BFS入度为0入队

**哈希表：**
- 冲突解决：链地址法（拉链法）、开放寻址法（线性探测、二次探测、双重哈希）
- 装载因子 = 元素数 / 桶数，超过阈值需扩容
- Python dict：开放寻址 + 随机探测

## 三、数据库

**MySQL核心：**
- InnoDB vs MyISAM：

| | InnoDB | MyISAM |
|---|---|---|
| 事务 | ✅ | ❌ |
| 行锁 | ✅ | ❌（表锁） |
| 外键 | ✅ | ❌ |
| 崩溃恢复 | ✅ | ❌ |
| 全文索引 | ❌(5.6+支持) | ✅ |
| count(*) | 慢（遍历） | 快（存总数） |

- 索引类型：
  - 主键索引：唯一+非空
  - 唯一索引：唯一，允许NULL
  - 普通索引：无约束
  - 组合索引：遵循**最左前缀原则**
- 聚簇索引 vs 非聚簇索引：
  - InnoDB：**聚簇索引**（数据和主键索引存在一起）
  - MyISAM：非聚簇索引（数据单独存储）
- 覆盖索引：查询的列全在索引中，**不需要回表**
- 索引失效场景：对索引列用函数、隐式类型转换、LIKE '%xx'（左模糊）、OR条件中有非索引列、!=/NOT IN

**事务ACID：**
- 原子性(Atomicity)：undo log
- 一致性(Consistency)：约束+规则
- 隔离性(Isolation)：MVCC + 锁
- 持久性(Durability)：redo log

**隔离级别（弱→强）：**
1. READ UNCOMMITTED：脏读、不可重复读、幻读
2. READ COMMITTED(RC)：解决脏读，Oracle默认
3. REPEATABLE READ(RR)：解决不可重复读，**MySQL默认**，InnoDB通过MVCC+间隙锁部分解决幻读
4. SERIALIZABLE：全部解决，性能最差

**MVCC：**
- 每行数据隐藏列：trx_id（最后修改的事务ID）、roll_pointer（undo log指针）
- ReadView：活跃事务ID列表，判断数据版本是否可见
- RC：每次SELECT生成新ReadView
- RR：事务第一次SELECT时生成ReadView，后续复用

**SQL优化：**
- EXPLAIN type列（优→劣）：system > const > eq_ref > ref > range > index > **ALL（全表扫描）**
- UNION去重需排序，不需要去重用**UNION ALL**
- EXISTS vs IN：子表大用EXISTS，主表大用IN
- LIMIT优化：大偏移量用延迟关联

## 四、计算机网络

**TCP/UDP：**
- TCP：面向连接、可靠、字节流、全双工、点对点
- UDP：无连接、不可靠、数据报、开销小、支持广播/多播
- TCP首部最小20字节，UDP首部8字节
- TCP三次握手：SYN→SYN+ACK→ACK，防止已失效连接请求到达服务器
- TCP四次挥手：FIN→ACK→FIN→ACK，TIME_WAIT等待2MSL（确保最后一个ACK到达+让旧报文段消亡）
- TIME_WAIT过多：开启SO_REUSEADDR或缩短MSL

**TCP拥塞控制（四算法，必背）：**
1. **慢开始(Slow Start)**：cwnd从1开始，每收到一个ACK，cwnd翻倍（指数增长）
2. **拥塞避免(Congestion Avoidance)**：cwnd达到慢开始门限ssthresh后，每个RTT cwnd+1（线性增长）
3. **快重传(Fast Retransmit)**：收到3个重复ACK立即重传，不等超时
4. **快恢复(Fast Recovery)**：快重传后ssthresh=cwnd/2，cwnd=ssthresh（不是回到1）

- 注意：**CSMA/CD是数据链路层协议，不是TCP拥塞控制算法！**

**HTTP：**
- HTTP/1.0：短连接
- HTTP/1.1：长连接（默认Connection: keep-alive），管线化(pipelining)
- HTTP/2：多路复用、头部压缩、服务器推送、二进制帧
- HTTP/3：基于QUIC(UDP)，解决队头阻塞
- 状态码：
  - 200 OK | 301 永久重定向 | 302 临时重定向 | 304 未修改
  - **400 Bad Request** | **401 Unauthorized**（未认证）| **403 Forbidden**（无权限）
  - **404 Not Found** | **500 Internal Server Error**
  - **502 Bad Gateway** | **503 Service Unavailable** | **504 Gateway Timeout**

**HTTPS：**
- HTTP + TLS/SSL
- **非对称加密交换对称密钥，对称加密传输数据**（别搞反！）
- 流程：TCP握手→TLS握手（ClientHello→ServerHello→证书→密钥交换→Finished）→HTTP通信
- CA证书链：根CA→中间CA→服务器证书

**DNS：**
- 解析顺序：浏览器缓存→OS缓存→本地DNS服务器→根DNS→TLD DNS→权威DNS
- DNS用**UDP**端口53（报文<512B时），区域传送用TCP
- DNS劫持 vs HTTP劫持 vs CDN劫持

**其他高频：**
- ARP：IP→MAC，广播请求单播响应，工作在数据链路层
- ICMP：ping用，网络层协议
- NAT：私有IP↔公网IP转换，NAPT用端口号区分
- 子网掩码：/24 = 255.255.255.0，可用主机数 = 2^(32-n) - 2
- Cookie vs Session vs Token：Cookie存客户端，Session存服务端，Token无状态

## 五、编程语言基础（Python重点）

**Python：**
- GIL（全局解释器锁）：同一时刻只有一个线程执行Python字节码，**CPU密集型多线程无效**
- 可变类型：list, dict, set | 不可变：int, float, str, tuple, bool
- `is` 比较身份(id)，`==` 比较值
- `*args` 元组，`**kwargs` 字典
- 列表推导式比for循环快
- `copy.copy()` 浅拷贝，`copy.deepcopy()` 深拷贝
- 装饰器：`@functools.wraps` 保留原函数元信息
- 生成器：`yield`，惰性求值，节省内存
- `__new__` 创建对象，`__init__` 初始化对象

**Java（可能考）：**
- `==` 比较引用，`.equals()` 比较内容（String重写了equals）
- String不可变，StringBuilder线程不安全但快，StringBuffer线程安全但慢
- HashMap
