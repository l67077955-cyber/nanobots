## I/O密集型代码的典型模式

当前 `/root/.nanobot/workspace` 中**无任何实际代码文件**，所有目录均为空。nanobot系统源码扫描未完成（队友超时）。

以下是I/O密集型代码的完整分类，供对照排查：

### 1. 网络请求
```python
requests.get/post()          # 同步阻塞
httpx.Client().get()         # 同步模式
aiohttp.ClientSession()      # 异步但仍是I/O等待
urllib.request.urlopen()     # 标准库阻塞
```

### 2. 文件读写
```python
open("file").read()          # 大文件读取阻塞
Path("file").write_text()    # 写入阻塞
shutil.copy/copytree()       # 大量文件拷贝
json.load(open("big.json"))  # 大JSON解析
```

### 3. 子进程调用
```python
subprocess.run(["cmd"], capture_output=True)  # 等待进程结束
subprocess.Popen().communicate()              # 等待I/O完成
os.system("cmd")                              # 完全阻塞
```

### 4. 数据库操作
```python
cursor.execute("SELECT ...")   # 查询等待
cursor.fetchall()              # 大结果集传输
sqlite3.connect()              # 连接建立
```

### 5. Socket/网络通信
```python
socket.accept()       # 等待连接
sock.recv(4096)       # 等待数据
```

### 6. 日志/打印（轻量但累积）
```python
logging.info()        # 写文件时阻塞
print()               # stdout缓冲区满时阻塞
```

### 判断标准
- **CPU密集**：计算时CPU跑满，等待时间≈0（如矩阵运算、加密、压缩）
- **I/O密集**：大部分时间在**等待**外部响应，CPU空闲（如网络请求、磁盘读写、DB查询）

### 优化方向
| 模式 | 优化手段 |
|------|---------|
| 同步网络请求 | → `asyncio` + `aiohttp`/`httpx.AsyncClient` |
| 多个独立I/O | → `asyncio.gather()` 并发 |
| 大文件读写 | → 流式读取 `chunk`、`mmap` |
| 子进程 | → `asyncio.create_subprocess_exec` |
| 数据库 | → 连接池 + 异步驱动（`aiosqlite`） |
| 批量I/O | → 线程池 `ThreadPoolExecutor`（I/O场景下线程比进程轻量） |
