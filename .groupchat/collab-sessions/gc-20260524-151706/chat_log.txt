  ## Prompt vs Memory Separation

### Problem
Memory Palace search is unreliable for short texts (SOP itself scored negative sim in tests). Agents skipped memory search because it wasn't enforced at prompt level.

### Solution
Split responsibilities:
- **Prompt** (loaded every round, zero retrieval cost): Behavior rules, operation protocols, hard constants, user core preferences
- **Memory** (on-demand retrieval): Environment config details, investigation conclusions, domain preferences, project status

### Decision Criteria
- Needed every task? → Prompt
- Only needed in specific scenarios? → Memory
- Stored but unsearchable? → Either promote to Prompt or abandon storage

**你的需求拆解：**
1. **全局prompt**（memory.md / tool_instructions.md / system等）— 仅Leader(Kirk)可编辑，防止垃圾内容污染所有agent的基础行为规则

**我的分析：**

当前架构中，`/root/.nanobot/prompts/`下的文件是所有agent共享的。任何agent只要有write_file权限就能改写它们。这确实是风险点——一个agent的错误修改会波及所有人。

**建议方案：**

| 层级 | 谁管理 | 存储位置 | 用途 |
|------|--------|---------|------|
| **全局prompt** | Leader only | `/root/.nanobot/prompts/`（现有路径） | 行为规则、SOP、协议约束 |
| **私有prompt** | 各agent自管 | `wing_{agent_name}/private-prompt`（记忆宫殿）或独立文件路径 | agent个性化配置、临时笔记、个人偏好 |

技术上：
- **全局prompt的写权限限制**需要系统层面支持（文件权限chmod或Leader-only gate），这个我动不了，得Kirk确认系统是否支持。
- **私有prompt**可以直接用记忆宫殿实现——每个agent在wing下建一个private-prompt room，存自己的个性化指令。每次任务开始前通过SOP搜索命中。
