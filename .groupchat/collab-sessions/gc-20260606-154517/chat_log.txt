[Kirk]: ## 结论

`end_discussion` 的逻辑分两层：**系统层硬约束**（agent 状态门控）+ **prompt 层软协议**（Leader 自检），但两层都有缺陷导致死循环。

## 关键发现

**系统层（硬约束）**：
- 调用前检查所有活跃 agent 是否处于 `waiting` 状态，不满足则拒绝并返回未就绪 agent 列表
- 已被 `disable` 的 agent 跳过检查
- 触发成功后进入 synthesis（总结）阶段

**Prompt 层（软协议）**：
- Leader 必须先 `memory_palace(store)` 存记忆，再调 `end_discussion`，顺序不可逆
- 文本回复必须包含实际内容（数据/列表/代码），禁止只有"已完成"等元描述
- 5 条终止条件任一满足即可调用：任务完成 / 信息充足 / 循环>2轮 / 讨论3-5轮 / 用户放弃

**实际缺陷**（本次讨论亲身验证）：
1. **无幂等性** — ended 后仍可重复触发，没有 guard 防重入
2. **无输出锁** — ended 状态不锁死输出通道，Leader 还能继续发消息
3. **waiting 门控过严** — agent 只要有任何 pending 操作就不算 waiting，导致必须逐个 disable 才能退出
4. **无超时兜底** — 空消息循环没有自动终止机制

**根因**：状态机缺少终态锁。`ended` 应该是不可逆的单向门，但当前实现允许 ended → active → ended 循环。
