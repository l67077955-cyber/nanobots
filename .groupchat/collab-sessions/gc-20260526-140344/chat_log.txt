## 结论

当前工具调用的"可见性"是**隐式的、不透明的**，用户的需求完全合理——每条工具调用应该显式标注谁可见、看到多少字。

## 关键发现

**当前两条展示路径，可见性完全不同：**

| 路径 | 谁看到 | 看到什么 |
|---|---|---|
| **UI 展示**（broadcast_view.py） | 仅用户 | 🟡→🟢 实时编辑，`tool_result_brief` 截断预览 |
| **History 传递**（build_tool_log L1535） | 其他 agent | `result_max_chars` 截断后的工具日志，写入共享 history |

**具体问题：**

1. **UI 展示只给用户看**——`engine._send()` 发到 Telegram，agent 之间看不到这条消息。agent 看到的是 history 里 `build_tool_log` 生成的文本，两者格式、截断长度、内容都可能不同。

2. **build_tool_log 的截断逻辑**（L1568-1624）：有 `result_max_chars` 限制（broadcast 模式默认 20000），超出后截断并标注字数。但这个截断对所有 agent 统一，没有"给 Leader 全文、给队友压缩"的差异化。

3. **chatroom_send 是唯一有明确 target 的工具**——broadcast_view.py L49-72 专门处理，显示 `┄ Kirk → Harper ┄`。其他所有工具（web_search、exec、read_file）都没有 target 概念，默认"用户可见 + history 全员可见"。

4. **用户想要的格式**：`kirk→ ping xxx.com ) visible-to: harper (compressed 56chars) lucas(full-text 100chars)`——这需要给每个工具调用增加一个 **visibility 策略层**，当前架构完全没有这个层。

## 备注

实现这个需求需要改动的位置：
- **broadcast_view.py L78-89**：`on_tool_start` 的 else 分支，需要接收 visibility 信息并渲染
- **engine.py L1535 `build_tool_log`**：需要按 agent 角色差异化截断
- **broadcast.py L1029-1035**：history 写入时需要区分每个 agent 看到的工具日志版本
- **核心问题**：当前 history 是共享的单一份，要实现差异化可见需要改成 **per-agent history** 或在写入时做 mask——这是架构级改动，不是加个显示格式那么简单。
