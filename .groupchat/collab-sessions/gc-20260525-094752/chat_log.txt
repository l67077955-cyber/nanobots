[Kirk]: 现在逻辑完全清晰了。**这是一个设计层面的 bug，不是简单的 User 特殊情况。**

让我重新梳理整个 pool 模型：

**`allocate(sender, recipients)`**:
- 消耗 **sender** 的 slot（`sem[sender].acquire()`, `_available[sender] -= 1`）
- 记录 `pending[recipient].append(sender)`

**`release_unread(agent)`**:
- 遍历 `pending[agent]` 中的每个 sender
- 释放 **sender** 的 slot（`sem[sender].release()`, `_available[sender] += 1`）

**`mark_replied(agent, to_sender)`**:
- 从 `pending[agent]` 移除 `to_sender`
- 释放 **to_sender** 的 slot

**`allocate_user(recipients)`**:
- 消耗 **recipient** 的 slot（`sem[r].acquire()`, `_available[r] -= 1`）
- 记录 `pending[r].append("User")`

**Bug**: `allocate_user` 消耗的是 **recipient（agent）** 的 slot，但 `release_unread(agent)` 释放的是 **sender（"User"）** 的 slot。两条路径不对称！

对于 agent-to-agent：A 发给 B → 消耗 A 的 slot → B 不读 → 释放回 A 的 slot。**一致。**

对于 user-to-agent：User 发给 B → 消耗 B 的 slot → B 不读 → 尝试释放回 User 的 slot → **User 不在 pool 中，释放失败！**

```python
self._available[target] = self._available.get(sender, 0) + 1
```
