[Kirk]: ## 当前逻辑

### 触发时机

`run_loop.py` 第142-157行：**每轮 `broadcast_round()` 返回后**立即触发，不是只在 `end_discussion` 时。也就是说每次群聊轮次结束都会跑。

### 执行流程

`_auto_memory.py` 的 `auto_store_memories()` 做了3次串行 LLM 轮询：

| 轮次 | 提取目标 | 存入位置 | Room 命名 |
|------|---------|---------|-----------|
| Poll 1 | 工具/方法/踩坑/技术结论 | `wing_code` | `round-{日期}-{话题slug}` |
| Poll 2 | 用户指令风格/输出偏好/交互习惯 | `wing_user` | `preferences-{日期}` |
| Poll 3 | 事实数据/跨任务发现/规则约定 | `wing_agent` | `discoveries-{日期}` |

### 每轮的具体步骤

1. **构建对话文本** — 从 `engine._history` 取完整对话，每条消息截断800字，总计上限12000字
2. **LLM 提取** — 用 `summarize_model`（默认 gpt-4.1-nano）+ temperature=0.3 调用 provider，传入对应的提取 prompt
3. **质量过滤** — 内容 <50字 或 前20字含"无" → 跳过不存
4. **直接写入 ChromaDB** — 调用 `tool_add_drawer()`，绕过 LLM tool loop，`added_by="auto_memory"`

### 降级保护

- 对话 <100字 → 整体跳过
- 无 provider → 跳过
- 单轮 LLM 失败 → 记录 error，继续下一轮
- 整个 `auto_store_memories` 被 try/except 包裹 → 不阻塞主流程

### 关键设计决策

- **不经过 LLM tool loop**：直接调 `tool_add_drawer`，避免递归触发记忆存储
- **用低成本模型**：summarize_model（nano 级别），省 token
- **Room 按日期+话题命名**：同一天同话题会存到同一个 room，不同话题分开
- **wing_user 的 room 只按日期**：偏好是跨话题累积的
