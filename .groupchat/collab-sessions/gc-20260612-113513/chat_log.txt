[Kirk]: ## 结论

`forget` 工具已完整实现，位于 `nanobot/tools/forget.py`，支持你要求的两种删除模式：

### 使用方式

**1. 关键词匹配删除**
```
forget(keywords="memory_palace")   # 删除所有匹配 memory_palace 的调用
forget(keywords="curl xxx")        # 删除参数含 "curl xxx" 的调用
```

**2. 索引删除（针对并行调用批次）**
```
forget(indices=0)        # 删除上次批次中第1个工具调用
forget(indices=[0, 1])   # 删除前2个工具调用
```

### 实现机制

- `tool_loop.py` 每轮执行工具前，将当前批次的工具调用信息写入 `ForgetTool._shared["last_tool_calls"]`
- `forget` 工具匹配后返回 `__FORGET__:JSON` 哨兵
- `tool_loop.py` 检测哨兵，从 `messages` 列表中**永久删除**对应的 tool result 消息和 assistant message 中的 tool_calls 条目
- 删除后 LLM 后续调用完全看不到被删内容

### 测试结果

| 场景 | 结果 |
|------|------|
| `keywords="memory_palace"` | ✅ 匹配并返回删除计划 |
| `indices=0` | ✅ 删除第1个 |
| `indices=[0,1]` | ✅ 删除前2个 |
| 无匹配关键词 | ✅ 返回可用列表提示 |
| 空批次 | ✅ 返回"无上次调用" |

## 关键发现

- `tool_loop.py` 第 691-733 行已有完整的 `__FORGET__` 哨兵处理逻辑（删除 tool result + 清理 assistant tool_calls）
- `broadcast.py` 第 383-385 行已注册 `ForgetTool`
- 工具名用 `forget` 而非 `delete`，避免与数据库操作混淆

## 备注

- 当前只支持删除**上一轮**的工具调用，不支持跨多轮回溯（可后续扩展）
- 关键词匹配是大小写不敏感的子串匹配
