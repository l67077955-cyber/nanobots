```python
# Keep agent alive instead of killing it (mirrors timeout recovery)
_placeholder = (
    f"⚠️ [{name}] LLM调用出错（{err_short[:60]}），我仍在线。"
    f"等待队友消息后将继续工作。"
)
content = _placeholder
engine._add_message(name, _placeholder)
mailbox.send(name, ["All"], _placeholder)
...
continue  # stay alive like timeout branch
```

**问题链路：** LLM调用出错 → `continue` → 下一cycle再次调LLM → 再次出错 → 无限循环直到`max_cycles`。

对比第686-688行timeout recovery有`_timeout_recovery_count += 1; if >=1: break`，LLM error分支完全没限制。当OpenRouter持续异常时，Kirk每小时循环一次，发了18次「我仍在线」。

**修复方案（最小变更）：** 给LLM error也加一个和`_timeout_recovery_count`一样的recovery limit，超过1次就退出。

[Kirk]: ## 结论

**根因：** `broadcast.py` 第907行 LLM error 分支缺少退出限制。出错后 `continue` 回循环顶部，下一 cycle 再次调 LLM → 再次出错 → 无限循环直到 `max_cycles` 耗尽。OpenRouter 异常期间 Kirk 发了 18 次「我仍在线」。

**已修复：** 添加 `_consecutive_error_count` 计数器，连续错误 ≥3 次强制 `break` 退出，成功 cycle 时重置。

## 关键发现

- **文件：** `/root/nanobot-src/nanobot/groupchat/orchestra/broadcast.py`
- **对比：** timeout 分支有 `_timeout_recovery_count` 限制（第833行），error 分支完全没有
- **改动：** 3处（第693-695行声明、第912-921行计数+退出、第947行重置）
- **策略：** 允许首次错误恢复（保持 agent 存活），但连续3次失败后强制退出，防止刷屏

## 备注

- 阈值设为3而非1，因为单次瞬态错误（如网络抖动）不应直接杀死 agent
- 与 timeout recovery 的设计理念一致：给一次机会，但不无限重试
