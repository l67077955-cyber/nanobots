## 关键发现

### 系统一：HistoryContext（群聊历史压缩）

**文件结构（~1100行）：**
| 文件 | 行数 | 职责 |
|---|---|---|
| `context.py` | 306 | 主逻辑：add_message + maybe_compress |
| `message_converter.py` | 195 | history_to_messages + age_tool_log |
| `history_settings.py` | 242 | 配置中心，所有阈值参数 |
| `context_validator.py` | 65 | 压缩后自检验证 |
| `tool_pruning.py` | 320 | 迭代上下文裁剪 |

**双层压缩架构：**

**层1 — add_message（每条消息插入时）：**
- 消息数限制：超过 `max_messages`(50) 时保留最近N条 + head保护
- 字符预算：从尾部倒序填充，放不下时先尝试 `age_tool_log` 压缩工具日志，仍不行则跳过继续尝试更小的消息（`continue`，不再 `break`）
- Head保护：index_0 + 所有user消息（`keep_user_messages=True`）

**层2 — maybe_compress（消息数达 `compress_ratio × max_messages` 时触发）：**
- 结构：Protected Head | Compressible Middle | Protected Tail
- Middle区先 `age_tool_log` 预处理（创建新dict，不原地修改），再AI摘要
- AI失败则直接丢弃middle
- 重建时保持原始时序（不再把head全拉到前面）

**关键配置（`~/.nanobot/history_settings.json`）：**
```
max_messages: 50, max_context_chars: 100000
compress_ratio: 0.8, compression_keep_recent: 6
keep_user_messages: True, history_summarize_enabled: True
```

**之前9个bug的修复状态：全部已修复 ✅**
1. add_message贪心break → 改为continue ✅
2. add_message不尝试age_tool_log → 已添加 ✅
3. _TOOL_LOG_RE跨行匹配 → 改用 `[^\n]*?` ✅
4. maybe_compress就地修改 → 创建新dict ✅
5-9. 时序重建、省略提示预算等均已修复 ✅

### 系统二：CompressionEngine（记忆数据库压缩预览）

**文件：** `config/backend/core/compression_engine.py`（471行）

**三级cascade：**
| 级别 | 预算阈值 | 动作 |
|---|---|---|
| mild | ≥50% | 用已有gist替换body渲染 |
| aggressive | ≥85% | 折叠进topic summary |
| emergency | ≥95% | 硬裁剪到archived_memories |

**可替换性评分公式：**
```
score = min(4.0, age_days × 0.02) - 3.5 × log1p(access_count)/log1p(100) + priority_bonus + type_bonus
```
- 越老越可替换（+0.02/天，上限4.0）
- 越常访问越不可替换（log衰减）
- pinned/critical域 = 豁免，评分-∞

**v1限制：** 纯只读预览，不实际写数据库，需人工确认后才执行。

### 代码可读性评估

**优点：**
- 注释充分，中英混合但意图清晰
- 函数职责单一，每个方法做一件事
- 配置集中管理，getter函数命名清晰
- 有自检验证（`validate_context`）
- `CompressionEngine` 用dataclass，结构化程度高

**可改进：**
- `add_message` 偏长（~70行），混合了消息数限制和字符预算两个关注点
- `history_settings.py` 用函数getter而非dataclass，每次调用都 `_load()`（有缓存但不够优雅）
- `history_to_messages` 同时处理格式转换+预算裁剪+rank隔离，职责偏重

**总体判断：** Python代码质量高，逻辑直白，不需要特别费力就能理解。核心算法就是"三段切分→判断触发→AI摘要或丢弃"，没有复杂的数据结构或算法。
