[用户]: hook是懒加载的脚本吗
---
[Harper]: 不是懒加载，是**事件驱动触发**。

Git hook 是 Git 内置的脚本机制，放在 `.git/hooks/` 目录下。当特定 Git 事件发生时（比如 `checkout`、`commit`、`push`），Git 自动查找并执行对应名字的脚本。

```
.git/hooks/
├── post-checkout      ← checkout完成后自动触发
├── pre-commit
├── prepare-commit-msg
└── ...
```

**懒加载 vs 事件驱动的区别：**

| | 懒加载 | 事件驱动（hook） |
|---|---|---|
| 触发方式 | 需要手动调用或定时轮询 | Git 操作自动触发 |
| 时机 | 按需/按计划 | 绑定到具体 Git 事件 |
| 示例 | systemd timer、cron job | post-checkout、pre-commit |

这个项目的 post-checkout hook 只要你执行任何 `git checkout`，无论何时何地都会自动运行，不需要手动调用。

[Retriever]: 不是懒加载。hook 是 **Git 原生的事件回调机制**，每次 `git checkout` 都会同步触发。

具体来说：

**不是懒加载**——它不是在"用到的时候才加载"，而是：
- **安装时机**：手动放到 `.git/hooks/post-checkout`（或者用 `git init` 时默认带模板）
- **触发时机**：每次 `git checkout` 完成后立即执行（同步阻塞）
- **生命周期**：脚本跑完才返回 shell 控制权给你

所以当你执行：
```bash
git checkout v-stable-20260517
```
这条命令不会直接返回——它会等 hook 跑完（包括去配置仓库切版本、写 version-lock.json）才会回到提示符。整个过程是同步的，没有延迟加载的概念。

类比：就像 npm 的 `postinstall` hook——装完包立刻跑，不是等你要用时才跑。

[Kirk]: ## 结论

**不是懒加载。** 是 Git 原生同步 hook，`git checkout` 时同步阻塞执行。

## 关键发现

- **触发方式**：Git 在 `git checkout`（切分支/标签）时自动调用 `.git/hooks/post-checkout`，hook 执行完之前 checkout 不返回
- **前置过滤**：`BRANCH_FLAG=0`（文件级 checkout）直接 `exit 0` 跳过；`BRANCH_FLAG=1`（分支/标签切换）才执行配置同步
- **执行模型**：同步阻塞，不是后台异步，不是按需加载

懒加载 = 用到时才加载。这个 hook = 切版本时立刻执行，执行完才放行。本质是**事件驱动的同步脚本**。
