## 代码逻辑：压缩触发机制

```
add_message()  → 即时 char-budget 裁剪（只计 message content）
maybe_compress() → 异步 AI 摘要（触发：消息数 ≥ max_messages × compress_ratio = 30×0.7 = 21条）
```

**用户配置 vs 代码默认值：**

| 配置项 | 用户值 | 代码默认 | 说明 |
|--------|--------|---------|------|
| max_messages | 30 | 50 | 用户更激进 |
| max_context_chars | 50,000 | 100,000 | 用户更激进 |
| context_window_tokens | 35,000 | 200,000 | ⚠️ 与 agent 默认矛盾 |
| compress_ratio | 0.7 | 0.8 | 21条触发压缩 |

**78k chars 超过 50k 限制的原因：** `max_context_chars` 只计算 message content，**不含 system prompt、工具定义、agent 指令**。实际发给 LLM 的 prompt = message content + system prompt + tool definitions，所以 50k message content 对应 78k+ 总 prompt 是正常的。
