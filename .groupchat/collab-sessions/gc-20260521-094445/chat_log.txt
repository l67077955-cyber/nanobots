[Harper]: ## 完整分析：上下文压缩 + 工具调用逻辑

### 四层压缩架构

整个系统存在**四层独立**的上下文压缩机制，在不同时机触发：

| 层级 | 位置 | 触发 | 作用 |
|------|------|------|------|
| **L1 add_message 裁剪** | `context.py:94-154` | 每次add_message() | 消息数≤50 + 字符≤100k |
| **L2 maybe_compress** | `context.py:156-265` | 每轮LLM后调用 | 中间区→AI摘要(500字) |
| **L3 tool_pruning** | `tool_pruning.py` + `tool_loop.py:216` | tool_loop迭代2+ | 旧工具结果→一行摘要 |
| **L4 conv_tail_prune** | `broadcast.py:1302-1320` | agent收到队友消息 | 对话尾保留9条+AI压缩 |

---

### L1: add_message 裁剪

保护head（index_0 + 用户消息），超限从尾部丢弃。
```
Protected Head | ... 丢弃超限 ... | 尾部保证存活
```

### L2: maybe_compress（AI摘要）

触发条件：消息数 ≥ 40（50×0.8）

结构：Protected Head(保护用户消息) | **Compressible Middle**(→AI摘要) | Protected Tail(最近6条)

关键步骤：压缩前对所有中间消息执行 **age_tool_log()**——删除`[工具调用记录]`的result_preview，只保留骨架：
```
• web_search(trump xi meeting) → Found 5 results... (1,234字)
→ • web_search(trump xi meeting) → (1,234字)
```
然后用 `openai/gpt-4.1-nano` 做500字中文摘要，失败则直接丢弃中间区。

### L3: tool_pruning（迭代内裁剪）

tool_loop第2轮起，**发送给LLM前创建裁减副本**（不修改master messages）：
- 预估总字符 > 200k×0.3 → 触发
- 保留最近3轮assistant消息
- 之前的 tool role 消息如果 > 4k字，替换为一行摘要
- 新工具结果继续正确追加

### L4: conv_tail_prune（广播模式）

agent被队友消息唤醒时：
- 保留系统提示前缀不动
- 保留最后9条（3轮）对话
- 中间消息→AI摘要→追加到最后一条system msg末尾（保持prefix caching）

---

### 工具调用执行流程

tool_loop.py 的核心循环：

```
循环 {
  Phase 0: 校验 → context pruning(L3)
  Phase 1: call_LLM → 拿到 tool_calls
  Phase 2: 预处理 → dedup去重 + 权限检查
  Phase 3: asyncio.gather 并行执行所有工具
  Phase 4: 后处理 pipeline:
            normalize → truncate → persist → inject_meta
  Phase 5: 结果追加到 messages
  Phase 6: 中断检查 → 收到中断信号则 break
}
```

### 工具结果后处理 (result_processor.py)

完整 pipeline:
1. **normalize** — bytes/dict/list→str；多模态list透传
2. **truncate** — 按工具类型不同策略：
   - `exec` → 10k字, head_tail(一半头+一半尾)
   - `web_fetch` → 8k字, head_only
   - `web_search` → 5k字, head_only
3. **persist** — 截断的完整结果落盘到 `/tmp/nanobot/tool_storage/`
4. **inject_meta** — 追加 `exit_code | URL | Query | Duration`
