`/prompt` 整体架构清晰——组件化管线、模板变量展开、可见性控制、排序/增删都设计得不错。但有一个**确认的 bug** 和几个设计瑕疵。

## 确认的 Bug：`broadcast_hint` 模板变量未定义

`prompt_builder.py` 第 101-137 行，`broadcast_hint` 模板使用了 4 个变量：

```
{{agent_idx}}  {{total}}  {{teammates}}  {{user_question}}
```

但 `build_agent_prompt()` 第 500-513 行定义的模板变量只有：

| 变量 | 是否定义 |
|---|---|
| `{{agent}}` | ✅ stable |
| `{{members}}` | ✅ stable |
| `{{tools}}` | ✅ stable |
| `{{others}}` | ✅ stable |
| `{{identity}}` | ✅ stable |
| `{{datetime}}` | ✅ volatile |
| `{{round}}` | ✅ volatile |
| **`{{agent_idx}}`** | ❌ **未定义** |
| **`{{total}}`** | ❌ **未定义** |
| **`{{teammates}}`** | ❌ **未定义** |
| **`{{user_question}}`** | ❌ **未定义** |

**结果**：这 4 个变量会原样保留为字面字符串注入到 agent 的 system prompt 中。你可以验证——我自己的系统提示里就写着 `你是 {{agent_idx}}/{{total}} 号成员，代号 Kirk | 队友: {{teammates}}`，`{{agent}}` 被正确展开了，但其余 4 个没有。

**修复方案**：在 `build_agent_prompt()` 的 `stable_tpl_vars` 中补充这 4 个变量。`agent_idx` 和 `total` 需要从调用方传入（当前函数签名没有这些参数）。

---

## 设计瑕疵（非 bug）

### 1. `_CONDITIONAL_TAGS` 误导
`settings.py` 第 328-331 行：
```python
_CONDITIONAL_TAGS = {
    "broadcast_hint": "广播模式",
    "leader_prompt": "Leader",
}
```
UI 上显示 `[仅广播模式]`，暗示 broadcast_hint 只在广播模式下注入。但 `build_agent_prompt()` 里**没有任何条件判断**——只要模板非空就注入。`leader_prompt` 的条件注入是通过 visibility 系统实现的，而 `broadcast_hint` 没有。标签是假的。

### 2. Pre-history 组件无法使用 `{{datetime}}` / `{{round}}`
第 542 行：
```python
content = self._expand_template_vars(raw, all_tpl_vars if past_history else stable_tpl_vars)
```
history 之前的组件只拿到 stable vars。这是为了 KV cache 稳定性（设计意图正确），但 UI 的变量提示 `💡 变量: {{agent}} {{members}} {{datetime}} {{round}}...` 没有说明这个限制，用户可能在 pre-history 组件里用 `{{datetime}}` 然后发现不生效。

### 3. `{{identity}}` 是个隐藏炸弹
`stable_tpl_vars` 里包含 `{{identity}}`，展开后是整个 `_build_identity()` 的输出（平台信息、workspace 路径、guidelines，约 1500 字）。如果用户在某个模板里不小心用了 `{{identity}}`，会注入一大段内容。当前默认模板没有使用，但作为可用变量暴露在 UI 提示里，容易误用。

[Kirk]: ## 结论

`/prompt` 有一个确认的 bug + 三个设计瑕疵。

## 确认的 Bug：`broadcast_hint` 模板变量未定义

`broadcast_hint` 模板用了 `{{agent_idx}}` `{{total}}` `{{teammates}}` `{{user_question}}` 四个变量，但 `build_agent_prompt()` 的模板变量表里**一个都没定义**，函数签名也没接收这些参数。结果：变量原样作为字面字符串注入 agent prompt（我自己的系统提示里就能看到 `你是 {{agent_idx}}/{{total}} 号成员`）。

**修复**：`build_agent_prompt()` 签名加 `agent_idx, total, teammates, user_question` 参数，`stable_tpl_vars` 补上这四个变量。

## 设计瑕疵

1. **`_CONDITIONAL_TAGS` 标签造假** — `broadcast_hint` 标注 `[仅广播模式]`，但实际无条件注入（`leader_prompt` 的条件注入是通过 visibility 系统实现的，`broadcast_hint` 没有）
2. **Pre-history 组件变量限制未说明** — history 之前的组件只能用 stable vars，`{{datetime}}` `{{round}}` 不可用，但 UI 提示里列出了所有变量
3. **`{{identity}}` 隐藏炸弹** — 展开后约 1500 字，作为可用变量暴露在 UI 中容易误用
