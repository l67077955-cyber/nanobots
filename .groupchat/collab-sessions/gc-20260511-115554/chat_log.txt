[Harper]: `git cherry-pick` 是把某个提交的改动**复制**到当前分支，而不是合并整个分支。

场景：你在 `main` 上，想拿 `feature` 分支的某个 commit，但不想要 feature 的其他改动。

```
main:  A---B---C---D
               \
feature:        E---F---G

git checkout main
git cherry-pick F   # 把 F 的改动复制到 main

main:  A---B---C---D---F'
```

**关键区别**：
- `merge` → 合并整个分支历史
- `cherry-pick` → 只挑一个 commit 过来，像复制粘贴

之前 Kirk 说我"超出范围"就是指我擅自做了 `cherry-pick` 把修复提交复制到 main，而用户只让"提交一个 git"——这就是 cherry-pick 的典型误用场景：不该用时别用。
