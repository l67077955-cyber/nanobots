[Harper]: ## 结论：代码 Bug，非数据汇聚问题

**根因**：`end_discussion` 在 synthesis 重试前就杀了引擎，导致重试机制形同虚设。

### 精确代码路径

```
Leader 调 end_discussion("三维度竞品分析完成，数据充分")
  → chatroom_tools.py L1125: _engine._running = False    ← ① 引擎已死
  → broadcast.py L817: _leader_ended_discussion = True
  → L1143: len("三维度竞品分析完成，数据充分")=12 < 400 → 触发重试
  → L1152: 注入警告, 重置 flag, continue
  → L693: cycle++
  → L719: if not engine._running: → True!               ← ② 引擎死了，break
  → 循环结束，重试从未执行
```

### 为什么不是 Kirk 说的"数据汇聚不足"

`comm_count=2` 是结果不是原因。即使 worker 共享了数据，Leader 的 synthesis 重试路径也是坏的——`continue` 回到循环顶，但 `engine._running=False` 导致 L719 直接 `break`，LLM 根本没机会看到那条"请给出完整总结"的警告。

### 修复

**最小改动**（broadcast.py L1152 附近）：
```python
engine._running = True   # 恢复引擎，让重试能执行
continue
```

**更干净的修复**：把 `_engine._running = False` 从 `end_discussion.execute()` 移到 synthesis 检查通过后的 `break` 之前（L1176）。

[Kirk]: **根因是 `end_discussion` 工具与 synthesis 重试机制之间的时序冲突 bug。**

`end_discussion.execute()` 在 `chatroom_tools.py` L1125 立即设置 `engine._running = False`，但 `broadcast.py` 的 synthesis 验证（L1141-1177）在检测到文本过短或质量不达标时，注入警告后 `continue` 回到 `while True` 顶部，被 L720 的 `not engine._running` 检查直接 `break`。LLM 永远看不到注入的警告，重试从未真正执行。

**执行时序：**
1. Leader 同一轮输出 `end_discussion` + 短文本（"三维度竞品分析完成，数据充分"，12字符）
2. `end_discussion.execute()` → `engine._running = False`
3. 短文本已发送给用户（L1135-1137）
4. synthesis check：12 < 400 → 注入警告，`continue`
5. 回到 `while True` → L720：`engine._running=False` → `break`
6. 用户只看到12字，完整总结从未生成

**两条重试路径都受影响**：L1153（长度不足）和 L1177（quality_check 失败）。synthesis 验证机制自上线以来从未成功触发过一次重试。

**修复**：`broadcast.py` L720 改为 `if not engine._running and not _leader_ended_discussion: break`，让 synthesis 重试豁免引擎停止检查。
