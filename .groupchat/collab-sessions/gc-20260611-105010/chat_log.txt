## 实际使用的参数

`context_pruning` 只有3个参数被真正使用：
1. `soft_ratio` → `pruning_soft_ratio()` → 控制何时触发修剪（>30%窗口）
2. `keep_recent` → `pruning_keep_recent()` → 保护最近N轮assistant消息
3. `soft_max_chars` → `pruning_soft_max_chars()` → 单条工具结果最大字符数

1. Telegram UI 仍显示能修改它们（通过 `update_field`）
2. 但修改后没有任何实际效果

[Kirk]: ## 结论

`history_settings.py` 中有 **4个无用/弃用参数**，它们在 defaults 中定义、Telegram UI 中可调，但运行时从未被读取，改了也不生效：

| 参数 | 默认值 | 位置 | 问题 |
|---|---|---|---|
| `context_pruning.hard_ratio` | 0.5 | L75 | 无getter，运行时零调用 |
| `context_pruning.soft_head_chars` | 1500 | L78 | 无getter，运行时零调用 |
| `context_pruning.soft_tail_chars` | 1500 | L79 | 无getter，运行时零调用 |
| `tool_results.html_detect_enabled` | true | L54 | 无getter，tools/中零引用 |

## 关键发现

- **判断方法**：全项目 grep → 有 defaults 定义 + Telegram UI 控件 + 测试引用，但**无 getter 函数**且运行时零调用 = 死参数
- **实际生效的 context_pruning 参数只有3个**：`soft_ratio`、`keep_recent`、`soft_max_chars`，各自有 getter 被 `tool_pruning.py` 调用
- `hard_ratio` 看起来是早期"硬裁剪"设计残留，后来被 `soft_max_chars` 替代；`soft_head_chars`/`soft_tail_chars` 是"软裁剪保留头尾"设计残留，从未实现；`html_detect_enabled` 是 HTML 检测转 markdown 功能的开关，功能本身从未实现

## 备注

- 这4个参数在 Telegram `/hs` 设置界面中仍可修改，但改了毫无效果——属于误导性 UI
- 建议清理：从 defaults 删除、从 Telegram callbacks 删除对应 UI 控件、从测试中移除相关用例
