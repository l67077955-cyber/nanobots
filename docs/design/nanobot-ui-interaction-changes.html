UI 交互变化 — 你在 Telegram 里会感觉到什么

两个 commit 落地后的用户视角前后对比 · 共 4 处可感知变化 + 1 处刻意零变化
一句话：向导终于对你的第一次输入有反应了（以前第一条必被吞进群聊）、新建 Agent 的模型按钮从"点了没反应"变成"点了就走"、群里其他人按你的面板按钮会被拦截。其余交互——确认条、面板导航、按钮长相——全部保持原样。

重构 commit（4bab58c8f）· 刻意做到零可见变化

你在 Telegram 里感觉不到它的存在。所有按钮、面板、流程与之前完全一致；连你聊天记录里的旧按钮都继续有效（线上前缀一个没改）。它改变的是幕后保险：今后任何人写出"生成了但没人接"的按钮，会在测试阶段被拦下，而不是部署后变成又一个静默死按钮。

⚠️ 同样重要：这些痛点还没变（后续批次）

  • 30 秒确认窗仍然偏短 —— 长人设写完回来确认会超时，输入内容无处找回
  • 改完超参后状态残留 —— 之后发的普通聊天仍会被当成"待确认输入"拦住（bug #7，未修）
  • 切模型仍是两个旅程 —— 先 /editprovider 注册，再 /editagent 绑定；模型选择器仍是平铺长列表
  • 选了哪个提供商不决定路由 —— 同名模型多提供商时仍由文件顺序决定（绑定未存 provider）
  • 模型列表缓存 —— 运行期仍无法强制刷新，重启才重新拉取

这五项是下一批工作（settings_store 收敛 → agent 卡片 + 芯片级联选模型）的输入。
